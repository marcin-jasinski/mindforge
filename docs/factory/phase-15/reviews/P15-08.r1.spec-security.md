- id: S1
  severity: major
  confidence: 0.75
  location: docs/project/deployment.md:60
  claim: The CLI section names only `DATABASE_*` and `OPENROUTER_API_KEY` as the configuration the CLI reads, but the CLI does not start without a `JWT_SECRET` of at least 32 bytes.
  evidence: `AccountConfig` (src/main/java/dev/mindforge/infrastructure/config/AccountConfig.java:25-29) has no `@Profile` and creates `JwtService` in every profile, including `cli`. `JwtService` calls `Keys.hmacShaKeyFor(secret.getBytes(...))` (JwtService.java:30), which throws for a key shorter than 32 bytes. `application.yml:94` defaults `jwt-secret: ${JWT_SECRET:}` to empty. Concrete case: an operator runs `java -jar mindforge.jar --spring.profiles.active=cli pipeline ...` on the host with only `DATABASE_*` and `OPENROUTER_API_KEY` exported, as the section tells them. The context fails at startup with a weak-key exception, and the run does not start. The compose override gives a dev secret only to the `app` container, not to a host `java -jar`.
  fix: Add `JWT_SECRET` to the list of variables the CLI needs (for example "(`DATABASE_*`, `OPENROUTER_API_KEY`, and `JWT_SECRET`, which must be set even though the CLI issues no tokens)"), or write "set the same variables as the server, see Configuration".

- id: S2
  severity: minor
  confidence: 0.7
  location: docs/project/deployment.md:100
  claim: The description of exit code 2 leaves out two refusals that the code reports as 2, and its claim that a retry with the same input always fails again is not true.
  evidence: PipelineCommandRunner.java:144 returns REFUSED for "cannot read file", and QuizCommandRunner.java:103 returns REFUSED for "nothing to quiz" (a knowledge base with nothing to quiz). Neither one is a usage error, an unknown user or knowledge base, a non-owner, or a refused upload. Also, "before a run was queued" applies only to the pipeline command. Neither refusal is permanent: the file can become readable, and the knowledge base can get pages. So a retry with the same input can succeed, which contradicts "Retry with the same input fails again".
  fix: Add "an unreadable file" and "(quiz) a knowledge base with nothing to quiz" to the list. Change the last sentence to "Retry with the same input fails again until the input or the data changes", or delete it.
