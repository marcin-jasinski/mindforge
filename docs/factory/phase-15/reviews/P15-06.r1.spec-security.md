- id: S1
  severity: minor
  confidence: 0.6
  location: src/main/java/dev/mindforge/cli/PipelineCommandRunner.java:245
  claim: A repeated `--lesson-id` (for example `--lesson-id=a --lesson-id=b`) is silently treated as absent, so the file is ingested with no lesson instead of being refused.
  evidence: D08 says "`--lesson-id` single value; blank = absent". `option()` returns null when `values.size() != 1`, so `run()` passes `lessonId = null` to `DocumentUpload` and `ingest` admits the file as a lesson-less document. The user asked for a lesson and gets none, with exit 0. For `--file/--kb/--user` the same null gives a usage error (exit 2), but for `--lesson-id` null means "absent", not "invalid".
  fix: Treat more than one `--lesson-id` value as a usage error (exit 2), for example check `args.getOptionValues("lesson-id")` size > 1 before calling `ingest`.
