## Reasoning
- `begin` exists only to free an HTTP request (QuizService.begin javadoc: "so the request does not wait for the model"). A terminal has no such need; D01 also makes the CLI an in-process run, so blocking is fine.
- `start` is a public method on the same service; `answer` is the same path as the web, which meets the plan checklist ("submits answers through the same QuizService path").
- B needs a poll loop, sleep and the error path of `isPreparing` (NotFoundException when no usable question): more code, more tests, no gain. Its `preparing` map is in-JVM and the pool is `generation`; it adds async state to a batch process.
- C: scope options are not required by plan 15.2 ("interactive terminal quiz"). `StudyScopes` is package-private in api.controller; moving it is a speculative refactor. Add later on top of A without a break.
- `start` throws NotFoundException for no pages or no usable question: the runner catches it, prints the message to stderr, exits non-zero.
- Per answer print score and feedback only (Graded has no reference answer); summary at end; EOF ends the quiz.
- Both the model call and the commit are inside `start`/`generate`; the "no model in a transaction" rule is the service's job, not changed.
