## Reasoning
- PipelineConfig.java wires SseProgressNotifier by concrete type into IngestPipeline, LintService, RunWorker (lines ~117-144), and RunController. Changing the pipeline beans to the ProgressNotifier port is a type-only change and aligns with hexagonal rules.
- Under cli there is no server (D02), so SSE has no subscribers. Keeping it would add a dead emitter map. A console notifier replaces it: `SseProgressNotifier` bean gets `@Profile("!cli")`, the console one `@Profile("cli")`.
- Failure mode 1: RunController injects the concrete SseProgressNotifier. Without that bean the cli context fails at startup. D02 already gates the controllers on a web application (add if the context-load test fails); that test catches it.
- Failure mode 2: drain claims the OLDEST queued run (D01), which may not be the CLI's run. The console notifier must label lines with runId, or filter by the CLI's run id, so output is not misattributed.
- Failure mode 3: the port is best-effort and must never throw. Catch and swallow in the console notifier (stdout closed, broken pipe). Print to stderr or stdout consistently; test that it does not throw.
- B adds a registry and listener lifecycle (leaks, ordering) for one consumer: speculative. C cannot show steps.

## What would change my mind
A second in-process consumer for progress (e.g. a web UI in the same JVM as the CLI), which would justify fan-out.

## Implementation notes
- `PipelineConfig`: change the `SseProgressNotifier progressNotifier` params in the IngestPipeline, RunWorker and LintService beans to `ProgressNotifier`. Keep the SSE bean `@Profile("!cli")`, with `RunController` still taking the concrete type (web only).
- New `dev.mindforge.cli.ConsoleProgressNotifier implements ProgressNotifier`, `@Profile("cli")` bean in `CliConfig`. Prints `[runId-short] step done/total` for each `RunProgress`; filters by the CLI's run id if set; never throws.
- Tests: plain unit test for the console notifier (output format; swallows a failing PrintStream); the cli context-load test from D02 asserts the bean is a ConsoleProgressNotifier.
