## Options
| id | option | correct | fit | simple | risk | reversible |
|----|--------|---------|-----|--------|------|------------|
| A  | Extension map in CLI, else octet-stream | 5 | 5 | 5 | 5 | 5 |
| B  | probeContentType + fallback | 3 | 3 | 3 | 3 | 4 |
| C  | --mime option defaulted by A | 4 | 3 | 3 | 4 | 4 |
## Reasoning
A mirrors the SPA mapping (frontend documents.ts#mimeType), is deterministic across OSes, and unknown types fall through to the sanitizer's normal refusal, so the allowlist stays the parser registry.
B adds OS-dependent behaviour (null or text/x-markdown for .md) for no gain. C adds a flag nobody needs yet (speculative); it can be added later without breaking A.
## What would change my mind
A real need to ingest files with non-standard extensions.
## Implementation notes
Private static Map<String,String> in the CLI command (lowercase extension lookup): md/markdown -> text/markdown, txt -> text/plain, pdf -> application/pdf, docx -> the DOCX MIME type; default application/octet-stream.
