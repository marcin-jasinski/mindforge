| id | option | correct | fit | simple | risk | reversible |
|----|--------|---------|-----|--------|------|------------|
| A  | first non-option arg is command; runner no-ops otherwise; unknown -> usage + non-zero exit | 5 | 5 | 4 | 4 | 5 |
| B  | `--file` present -> pipeline else quiz | 2 | 3 | 5 | 1 | 3 |
| C  | sub-profiles `cli,pipeline` / `cli,quiz` with @Profile | 3 | 3 | 3 | 3 | 3 |
| D  | A plus wrapper shell scripts | 4 | 3 | 2 | 4 | 4 |

## Reasoning
- B: a forgotten or mistyped `--file` silently starts an interactive quiz (or the reverse). In a scripted pipeline with no stdin, quiz would hang or fail oddly. Selection by inferred intent fails silently.
- C: the checklist says `--spring.profiles.active=cli` must work for both. C breaks that (needs `cli,pipeline`). With only `cli`, neither runner runs and the process exits 0 doing nothing, or the web app starts. It also puts selection in config, not in a testable code path.
- A: the failure mode is loud (usage + non-zero exit). It meets the checklist line as written. The command check is a pure function of the args, so it is unit-testable with no Spring context. Scope notes no `cli` package or `@Profile` exists yet, so A adds one small concept.
- D: scripts are untestable here, are not in the scope, and `deployment.md` has no wrapper pattern. Add later if wanted, without cost.
- Operability risk that all options share (not decided here): a CLI process next to a live server interferes with ingest recovery (scope.md line 41, ADR-0015). Require the `cli` profile to disable the worker, and exit codes must be non-zero on failure so scripts can detect errors.

## What would change my mind
Evidence that Spring Boot cannot cleanly return a non-zero exit from a CommandLineRunner in this setup (then use ExitCodeGenerator), or a requirement for literal `mindforge-pipeline` executables.

## Implementation notes
- `dev.mindforge.cli.PipelineCommandRunner` and `QuizCommandRunner`, both `@Profile("cli")`, `CommandLineRunner`, wired in a `@Configuration`.
- Command = `args.getNonOptionArgs().get(0)` via `ApplicationArguments`; use `ApplicationRunner`. Runner no-ops if the command is not its own.
- A small shared check (or a third runner) for missing/unknown command: print usage, exit non-zero via `ExitCodeGenerator`.
- Labels `mindforge-pipeline` / `mindforge-quiz` are doc names only; commands are `pipeline` and `quiz`.
- Set `spring.main.web-application-type=none` and disable the ingest worker/recovery in `application-cli.yml`.
