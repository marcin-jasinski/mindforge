## Options
| id | option | correct | fit | simple | risk | reversible |
|----|--------|---------|-----|--------|------|------------|
| A  | web-application-type none in application-cli.yml; @Profile("!cli") on web config | 5 | 5 | 4 | 4 | 5 |
| B  | keep web stack, server.port 0 | 3 | 2 | 5 | 2 | 4 |
| C  | main() picks web type from args | 3 | 2 | 3 | 3 | 4 |
## Reasoning
- api/config holds SecurityConfig, SpaConfig, RateLimitConfig, ApiDocsConfig, JwtFilter. All are web adapters (hexagonal), so profile-gating them keeps the adapter boundary clean.
- B exposes the API from a short-lived process and starts the security stack for nothing.
- C hides config in main(), is not visible in yml, and is harder to test.
- Prefer a ConditionalOnWebApplication where possible. It needs no profile name and states the real reason. Use @Profile("!cli") only where a bean is web-only but still loads in a non-web context.
## What would change my mind
Spring Boot 4 context fails with type none because of controllers or filters that are component-scanned. Then a profile-gated scan is needed.
## Implementation notes
src/main/resources/application-cli.yml: spring.main.web-application-type: none. Add @ConditionalOnWebApplication to the api/config classes and to the @RestController classes (or @Profile("!cli")). Add a context-load test for the cli profile.
