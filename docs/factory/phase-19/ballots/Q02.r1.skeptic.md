## Reasoning
- The Discord value (src/main/java/dev/mindforge/discord/DiscordAllowlist.java) checks "where" and "who"; for Slack the
  "where" (team_id) is constant per install, so only a "who" check (caller's own team) has security value. A fails it.
- Evidence (Slack docs, slash-command payload; slack-edge SlashCommand type): a slash-command payload carries team_id,
  enterprise_id, user_id, channel_id — no user_team. Slack also states slash commands can be invoked only by users of
  the installing workspace. But message/file events (the upload handler) carry `user_team`/`source_team`, and external
  Slack Connect members can post files in a shared channel. So B must take the caller team as an input and reject when
  it is absent or unlisted; for slash commands resolve it via `users.info` (fail closed on API error) or, at minimum,
  pass the payload team and document Slack's own restriction. Unknown = reject, never "assume own team".
- E is too broad: an enterprise_id admits every workspace in the Grid org, and is absent outside Grid.
- C: ADR 0028 rejects DMs because a Discord DM has no guild, so membership cannot be checked
  (docs/adr/0028-...md: "A command from a DM has no guild and no roles"). A Slack DM carries team_id and the user's team,
  and a deactivated Slack user can no longer act, so the check is current. The rationale does not carry over; rejecting
  DMs also pushes private document uploads into channels. C is safe but over-restrictive; it is my second choice.
- D: a channel list is speculative config with no requirement (minimal-implementation.md); add later without breaking B.
- Failure detection: unit tests on the pure value (listed/unlisted team, listed team + external caller team, null
  caller team, empty set rejected by @AssertTrue); a log line at INFO with a reason code (not team ids in replies).

## What would change my mind
Evidence that Slack never delivers message/file events from external users to the app (then A-with-docs suffices), or a
human requirement that commands stay in channels (then C).

## Implementation notes
- `record SlackAllowlist(Set<String> teamIds)` in `dev.mindforge.slack`; compact ctor `Set.copyOf`;
  `boolean admits(String teamIdOrNull, String callerTeamIdOrNull)` returns true only when both are non-null and listed.
- `AppProperties.Slack.allowedTeamIds` (`mindforge.slack.allowed-team-ids`), `@AssertTrue` non-empty when bot/app
  tokens are set; field-specific message as in `AppProperties.Discord`.
- Slash commands: caller team from `users.info` (`user.team_id`) or payload `team_id` as decided in W02; file events:
  event `user_team` (fall back to `users.info`); null => reject. Check first, before rate limit and identity resolution.
- Fixed rejection reply naming no workspace; enterprise_id is not used for admission. New ADR 0033 in newest format.
