## Reasoning
- The key is persisted twice (`external_identities.external_id`, PK `(platform, external_id)` in V8, and `users.email` via
  ADR 0027), so a wrong key costs a data migration. Choose the key Slack itself documents: the user object `id` is
  unique per workspace and must be used "together with team_id" (Slack user-object reference). A rejects that contract.
- ADR 0027 says "Phase 19 reuses the same rule with its own platform prefix"; it fixes the email shape and the reserved
  domain, not the id alphabet. `ExternalAccounts.EXTERNAL_ID = [A-Za-z0-9]+` was written for Discord snowflakes.
  Widening it to `[A-Za-z0-9]+(?:-[A-Za-z0-9]+)?` keeps every address a plain dot-atom local part
  (`slack-t0123-u0456@users.invalid`), keeps the domain JDK-only, and makes the composite key self-describing.
- B is acceptable and simpler, but the key is a composite whose split exists only by convention (team id bodies can
  contain `U`/`W`). A maintainer reading `T0ABCU12W9` in a year cannot see the parts; `T0ABCU12-W9` they can.
- D adds an enterprise concept and a branch for a Grid deployment no plan task asks for (minimal-implementation.md:
  no speculative generality). Under C a Grid user in two admitted workspaces gets two accounts: safe, only redundant.
- The Discord port stays as-is: same `ExternalIdentityRepository`, no Slack-only port (plan 19 checklist).

## Implementation notes
- `ExternalAccounts`: `EXTERNAL_ID = Pattern.compile("[A-Za-z0-9]+(?:-[A-Za-z0-9]+)?")`; update the Javadoc and the
  exception message; add `ExternalAccountsTest` cases: `slack-t0123-u0456@users.invalid`, reject `a--b`, `-a`, `a-`, `a:b`.
- Slack adapter (`dev.mindforge.slack`): `String externalId = callerTeamId + "-" + userId;` where `callerTeamId` is the
  caller's own team (`user_team` / `user.team_id`), not the channel's `team_id`, so it agrees with the Q02 allowlist check.
  Length: ~11 + 1 + ~11 chars, well within `VARCHAR(64)`; no Flyway migration.
- Record the key shape in the Phase 19 Slack ADR (or an ADR 0027 consequence line) and in `CONTEXT.md` if it names
  external identities.
