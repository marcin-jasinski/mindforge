## Reasoning
- No path exists today that gives a Slack user a second KB: no bot command creates one, the bot account cannot sign
  in to the web (ADR 0027), and `src/main/java/dev/mindforge/cli` has no KB create call (grep empty). Scope.md: "a
  Slack user will own exactly the one provisioned knowledge base until linking (#43)". A selector would always show
  one item - code for a case that cannot happen yet (minimal-implementation.md "No Speculative Abstractions").
- ADR 0030 rejected "only or oldest, implicitly" because a user with several "gets uploads ... in a knowledge base
  they did not pick, or is locked out". E removes the first harm (never "oldest"; several => refuse, never guess) and
  the second is unreachable until #43, which will need its own selection design anyway.
- A costs a `view_submission` handler, modal JSON, private_metadata state and a second round trip per command, and
  it does not fit the upload path: a `file_share` message (Q04 A/B) has no `trigger_id`, so a modal there needs yet
  another button step. B carries all of A's code for the unreachable branch.
- E keeps every security constraint: the id comes from `KnowledgeBaseService.list(userId)` (owner-filtered) and is
  still passed through `requireOwner(kbId, userId)`; every port call keeps `kbId` first. No name is ever parsed.
- Reversible: E -> B later is additive (replace the refusal branch with a modal); no command syntax changes because
  no KB token is in the text. Needs a short ADR (Slack-scoped) stating the reason, as the question requires.

## What would change my mind
Evidence that a Slack user can own more than one KB in Phase 19 (an operator CLI KB create for another user, or #43
scheduled in this phase), or that Q04 picks a modal-based upload (C/D) so the modal code exists anyway.

## Implementation notes
- `dev.mindforge.slack.SlackKnowledgeBases` with `Optional<UUID> soleKnowledgeBase(UUID userId, SlackReply reply)`:
  `List<KnowledgeBase> owned = knowledgeBases.list(userId)`; if `owned.size() != 1` reply fixed text
  "This command needs exactly one knowledge base." and return empty; else `requireOwner(id, userId)` and return id.
- Used by `/mf-ask`, `/mf-quiz start` and the upload handler after allowlist -> rate limit -> ack -> resolve.
  Quiz answers take no KB (session stores it, Q12).
- Unit tests (plain Mockito): one KB -> its id; zero -> refusal; two -> refusal and no service call.
- ADR 0033-ish: "Slack commands act on the user's only knowledge base" - lists A/B/C/D as considered, links ADR 0030.
