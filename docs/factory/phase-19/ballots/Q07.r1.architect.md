## Reasoning
- DiscordRateLimiter and DiscordQuizSessions have no JDA type (read both files). Both are about 30 lines. The quiz cache is already keyed by internal UUID, so it is identical for Slack. Only the rate limiter key differs (long vs String).
- Two real callers exist now, so a shared class is not speculative. This is the same logic a third time after RateLimitInterceptor (D11 copied it only to keep tested web code unchanged; that reason does not apply to Discord code we own).
- Copying duplicates window logic with a subtle compute() and rounding rule; a fix in one place would be missed in the other.
- Risk of B is small: Discord has only DiscordConfigWiringTest, so a rename and a generic key (Long boxed) change no behaviour. Keep it to two classes, no interface.
- C violates adapter independence.

## What would change my mind
If the refactor would force changes to Discord tests or bean wiring beyond a rename, or the Slack bot needs different behaviour, choose A.
