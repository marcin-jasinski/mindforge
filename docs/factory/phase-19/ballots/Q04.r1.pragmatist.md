## Reasoning
- Minimal-implementation.md: "Build What You Need"; "No Speculative Abstractions". A is one event handler (`message` subtype `file_share`, `channel_type=im`), no modal, no view_submission, no `views.open` 3 s race.
- Privacy by construction: a DM to the bot is seen only by the uploader and the bot, and the DM reply is the platform's private equivalent required by ADR 0032 (last consequence). B and C let the file sit in a channel first; the bot cannot make that private.
- Q03/scope.md: a Slack user owns exactly the one provisioned "Slack" knowledge base until #43, so A needs no KB picker; a modal (C, D) is UI for a choice that does not exist yet.
- Discord precedent `discord/UploadCommand.java` maps directly: same `DocumentUpload(kbId, userId, UploadSource.SLACK, ...)`, same fixed refusal texts, same "queued" reply. Only the option source changes (text tokens instead of typed options).
- D adds a constraint: `file_input` caps files at 10 MB (Slack Block Kit file input reference), a second size limit that can differ from `AppProperties.Upload`; and C/D both need `trigger_id` handling plus `files.info`.
- Weakness of A: it depends on Q02 admitting DMs (if Q02 picks C, A is invalid) and on Q03 not requiring a modal; free-text tokens are a small grammar to parse. Both are reversible: a later modal path can replace the event handler without data change.
- Failure mode to design for: Slack redelivers an event not acked in 3 s. Ack first, then do allowlist -> rate limit -> resolve -> download -> ingest off the ack path; ignore events with `bot_id` or a non-`im` channel; ingest dedup by content hash makes a redelivery harmless.

## What would change my mind
Q02 rejects DMs, or Q03 picks a modal for every command (then D shares the same modal code and becomes the least new code).

## Implementation notes
- `dev.mindforge.slack.SlackUploadHandler` registered in `SlackBot` via `app.event(MessageFileShareEvent.class, ...)` (or `MessageEvent` filtered on subtype `file_share`); handle only `channel_type == "im"`, skip `bot_id != null`, exactly one file per message (more -> fixed refusal).
- Gate order as Discord: allowlist (team ids per Q02) -> `SlackRateLimiter` (one count per upload, D11) -> `ExternalIdentityService.resolve(ExternalPlatform.SLACK, ...)` -> KB per Q03 + `KnowledgeBaseService.requireOwner` -> `SlackFiles.read(file, maxBytes)` (Q08; `url_private_download`, bot token bearer, fixed host list, capped) -> `IngestionService.ingest(new DocumentUpload(kbId, userId, UploadSource.SLACK, name, mediaType, bytes, lessonId, newVersion))`.
- Text grammar: whitespace tokens `lesson_id=<value>` and `new_version` (or `new_version=true`); unknown tokens -> fixed refusal text naming the grammar. Reuse Discord's fixed refusal strings (adapt "Discord's CDN" to "Slack").
- Reply with `chat.postMessage` to the DM channel (private to the user); scopes `files:read`, `im:history`, App Home messages tab enabled; event subscription `message.im`.
