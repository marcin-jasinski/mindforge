## Options
| id | option | correct | fit | simple | risk | reversible |
|----|--------|---------|-----|--------|------|------------|
| A  | DM the bot with one file; `message`/`file_share` event in an `im` channel; message text carries `lesson_id=<id>` and `new_version`; knowledge base per Q03; reply in the DM; channel files ignored | 4 | 4 | 5 | 4 | 4 |

## Reasoning
- Plan 19.2 (implementation-plan.md:1653) names "commands `/mf-ask`, `/mf-quiz`, file upload handler": the upload is
  an event handler, not a third command. A and B match this; D adds a command the plan does not have.
- ADR 0032: knowledge bases are private and "Platform bots in Phase 19 (Slack) follow the same rule with the platform's
  equivalent of an ephemeral reply". A DM between the user and the bot is private for both the file and the reply,
  so A needs no `postEphemeral` and never puts a private document into channel history. B and C operate on files that
  are already public in a channel, and B needs `channels:history` (the bot reads every channel message) - a wide scope
  for one feature.
- ADR 0029 § Consequences / Q08: one capped downloader on a fixed host list. All options share it; none changes it.
- Discord precedent (`discord/UploadCommand.java`): one interaction, one reply "run is queued", fixed refusal texts,
  `lesson_id` + `new_version`. A keeps this one-step shape; C and D need two interactions (open modal, submit) plus
  `private_metadata` to carry state, which is more new concepts (minimal-implementation.md "No Speculative Abstractions").
- D: Slack's `file_input` element has a 10 MB limit, below `mindforge.upload.max-size` 50MB (application.yml:106), so
  Slack would refuse files every other channel admits - breaks the "same limits on every channel" constraint.
- C: a bot token reads a file only where the bot can see it; "works in any channel the user can see" is not true, so a
  new failure path ("bot is not in this channel") appears.
- Cost of A: a `message` event has no `trigger_id`, so A cannot open a modal. It fits Q03 B/D (a Slack user owns exactly
  one provisioned "Slack" knowledge base until #43, scope.md "Accounts"). It conflicts with Q02 C (reject DMs); Q02 C
  copies ADR 0028's reason ("a DM has no guild"), which is false on Slack (a DM event carries `team_id`).
- A is reversible: a shortcut (C) can be added later as a second entry over the same `SlackUploads` service.

## What would change my mind
Q03 choosing a Block Kit modal for every command (A cannot open one from a DM event; then C fits better), or Q02 rejecting DMs.

## Implementation notes
- `dev.mindforge.slack.SlackUploadHandler`: registered with Bolt `app.event(MessageEvent.class, ...)` (and
  `MessageFileShareEvent` if Bolt routes subtype `file_share` separately); act only when `channel_type == "im"`,
  `subtype == "file_share"`, no `bot_id`; ignore all other messages silently. `ack()` first, work async.
- Gate order (same as `DiscordCommandHandler`): allowlist (Q02, on `team_id` and the user's team) -> rate limit (one
  count per message, D11) -> `ExternalIdentityService.resolve(ExternalPlatform.SLACK, ...)` (Q01) -> kb (Q03,
  `KnowledgeBaseService.requireOwner`) -> download -> `IngestionService.ingest(new DocumentUpload(kbId, userId,
  UploadSource.SLACK, file.name, mediaType(file.mimetype), bytes, lessonId, newVersion))`.
- Exactly one file per message; more than one -> fixed text "Send one file per message.".
- Text grammar: tokens `lesson_id=<value>` and `new_version` (case-insensitive); anything else ignored; parsed by a
  package-private static `SlackUploadText.parse(String)` returning `record UploadOptions(String lessonId, boolean newVersion)`.
- Reply through the single Slack reply helper (Q09) into the DM channel; refusal texts copied from `UploadCommand`
  constants with Slack wording; never the exception message.
- Scopes: `im:history`, `files:read`, `chat:write`; App Home "Messages tab" enabled; document in deployment.md.
- `UploadSource.SLACK` appended after `DISCORD`; add to `ArticleFetcher.SCANNED_SOURCES` per Q15.
- ADR: "Slack uploads are files sent to the bot in a direct message".
