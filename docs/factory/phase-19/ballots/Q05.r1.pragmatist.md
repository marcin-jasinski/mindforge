## Options
| id | option | correct | fit | simple | risk | reversible |
|----|--------|---------|-----|--------|------|------------|
| A  | Text subcommands start / answer <text> | 4 | 5 | 5 | 4 | 5 |
| B  | Button + modal | 5 | 3 | 1 | 3 | 3 |
| C  | Empty = start, text = answer | 3 | 3 | 5 | 2 | 4 |

## Reasoning
- A mirrors Discord `/quiz start` and `/quiz answer` (discord/QuizCommand.java), so the same QuizService.next/answer calls and ownership checks apply.
- B needs block_actions and view_submission handlers, signature checks for each, and modal state. That is new concepts for a single-line limit that is acceptable in v1.
- C is ambiguous: an accidental empty command resets or starts a quiz, and an answer that is a word like "start" is mishandled.
- A is easy to extend: a modal can be added later without changing the command.

## What would change my mind
Evidence that users need long multi-line answers in practice.

## Implementation notes
Slack QuizCommand parses the first token: "start" begins the quiz; "answer <rest>" grades it. Anything else returns an ephemeral usage hint. Per-user session pointer per D05.
