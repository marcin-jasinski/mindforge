## Reasoning
- Slack docs: "Slash commands and message actions are _not_ shared — they are limited only to the team that has
  installed the app" (docs.slack.dev/apis/slack-connect). So for `/mf-ask` and `/mf-quiz`, `team_id` is the caller's team.
- But plan 19.2 has a "file upload handler" that is not a slash command (Q04 Context: `message`/`file_share` event).
  Events in a shared channel come from external members too, and they carry `user_team` that differs from `team_id`.
  A therefore admits Connect guests on the upload path: account provisioning + model spend. Hard objection.
- B costs one more `contains` on a field that is already in the payload; no `users.info` call, no new scope (E rejected
  as extra I/O and a failure path for zero gain).
- C: ADR 0028 rejected DMs because "a DM has no guild and no roles" — the reason does not carry over; a Slack DM
  carries `team_id` and the user's team. Q04 option A (DM the bot with a file) is the simplest upload path; C would
  kill it. Rejecting DMs can be added later without changing the allowlist shape.
- D: a channel list is speculative generality (`docs/standards/global/minimal-implementation.md`: "No Speculative
  Abstractions"); Discord's role list was optional and has no Slack need stated in plan 19.2. Can be added later.
- Enterprise Grid: list team ids only; ignore `enterprise_id`. Operators of an org-wide install list each workspace.
  Fail closed means a Grid workspace not listed is rejected, which is the safe default.
- Mirrors `discord/DiscordAllowlist.java` (pure record, `admits(...)`), so unit tests drive it without Bolt (plan 19.3).

## What would change my mind
Evidence that Slack events can omit the caller's team in a shared channel (then fail closed on null and maybe use E),
or a Q04 decision that uploads happen only via slash command/modal (then A becomes correct but B still costs nothing).

## Implementation notes
- `dev.mindforge.slack.SlackAllowlist`: `public record SlackAllowlist(Set<String> teamIds)` with compact constructor
  `teamIds = Set.copyOf(teamIds)` and `boolean admits(String workspaceTeamId, String callerTeamIdOrNull)`:
  false when either is null/blank or not in `teamIds`. Slash commands pass `team_id` for both; events pass
  `team_id` and the event's `user_team` (fall back to the event `team` field; null -> reject).
- `AppProperties.Slack`: `List<String> allowedTeamIds` + `@AssertTrue isAllowedTeamIdsSetWhenTokenSet()` (same shape
  as `AppProperties.Discord`). Property `mindforge.slack.allowed-team-ids`.
- Check runs first in each handler, before rate limit / identity / provisioning; fixed reply text that names no
  workspace (e.g. "This Slack workspace is not allowed to use MindForge."). For a rejected event (upload), reply
  ephemerally or ignore silently per Q09.
- New ADR (next number after 0032): "Slack commands are admitted by a fail-closed team allowlist on both the workspace
  and the caller's own team"; Considered Options: team_id only, reject DMs, channel list, users.info lookup.
- Tests: `SlackAllowlistTest` with `make*` helpers: listed/listed admits; external caller team rejected; null caller
  team rejected; empty list never admits.
