Checked and found correct:
- Bolt 1.55.0 `App.start()` and `App.use()` call `buildDefaultMiddlewareList` lazily (not in the constructor), so `SlackApp.messageListener` is set before it is read. The listener is added after `SingleTeamAuthorization` and `IgnoringSelfEvents`, so `context.client()` has the bot token.
- `EventRequest.getEventType()` is the event `type` ("message"); the subtype is a separate field, so all `file_share` messages reach the listener.
- The gate order in `SlackUploadHandler.upload` is allowlist -> rate limit -> file count/grammar -> resolve -> KB+requireOwner -> download -> ingest. The KB refusal is sent once by `SlackKnowledgeBases` (the handler returns null), and the exception mapping matches `UploadCommand`. A `RuntimeException` gives the fixed FAILED text and no exception message.
- `SlackUploadText.parse`: case-insensitive keys, an empty `lesson_id=` is refused, a repeated token is refused, and a null or blank text gives no options.
- `BoltSlackReply.parts` is extracted with the same behavior as before. `SlackMessageListener.toMessage` handles a missing or ill-typed field as null, and the size defaults to 0.
- `UploadSource.SLACK` is appended last. The mapper stores `name()`, so the ordinal does not shift.
