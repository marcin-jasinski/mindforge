- id: C1
  severity: minor
  confidence: 0.7
  location: src/main/java/dev/mindforge/slack/SlackBot.java:27
  claim: A transient failure during the first Socket Mode connect leaves the bot off until the process restarts, because Bolt's auto-reconnect is only enabled after the first connect succeeds and SlackBot does not retry.
  evidence: SocketModeApp.run(boolean) (bolt-socket-mode 1.55.0 bytecode) calls app.start(), then clientFactory.get() (which calls apps.connections.open in the SocketModeClientJavaWSImpl constructor), then client.connect(), and only after that client.setAutoReconnectEnabled(true). If apps.connections.open or auth.test fails (for example Slack is unreachable for a few seconds at deploy time), the exception propagates out of startAsync(). SlackBot.run catches it, logs one ERROR line and returns. The client field stays null, so the session monitor never runs, and nothing calls startAsync() again. Result: the web app runs with no Slack bot and no recovery. The ticket accepts "the app keeps running", but it does not state that the bot stays off after a transient error.
  fix: Either record in the ticket Notes and the ERROR message that a restart is needed after a start failure, or retry startAsync() a few times with backoff on a virtual thread before giving up.
