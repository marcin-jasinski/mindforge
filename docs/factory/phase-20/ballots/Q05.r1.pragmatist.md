## Reasoning
- ADR 0008 and web-security.md require env-driven CORS; C is a blocker, not a judge call.
- App is same-origin (deployment.md line 3, dev proxy), so a default origin admits nothing useful and only widens credentialed access to any page on localhost:4200 (A).
- B meets "origin from env var, never hardcoded, never *" and satisfies ADR 0008 with the least exposure. Small code: one bean, one .cors() call, one env.example line.
- The stale Vercel docs should be flagged to the human separately, not fixed here.
## What would change my mind
If the human wants the web-security.md localhost default kept verbatim, A. If the human wants ADR 0008 superseded, C.
## Implementation notes
CorsConfigurationSource bean in the security @Configuration; read CORS_ALLOWED_ORIGIN (blank = no allowed origins, empty list); allowCredentials true only when an origin is set; never "*". Call .cors(Customizer.withDefaults()) in SecurityConfig. Add CORS_ALLOWED_ORIGIN (empty) to env.example. Unit test for blank and set cases.
