## Reasoning
- The fix is a few lines and reuses the existing pattern: `RunReportService.java:47` already does `runs.findById(kbId, runId).orElseThrow(() -> new NotFoundException("Run"))`, and `GlobalExceptionHandler` maps `NotFoundException` to 404. It adds no new concept.
- Q10 is answered: a foreign id under one's own kb gives 404. Plan 20.1 says "Fix any gaps found". B would add an exception to an agreed rule, and other code would then have to follow that exception.
- Option A as written ("before the run starts") breaks an intended ordering. `RevertServiceTest.shouldRefuseWhileAnotherRunHoldsTheLease` asserts `verify(runs, never()).findById(any(), any())`, so the run is read only after the lease is claimed. A pre-check also returns 404 instead of busy when the lease is held. A2 keeps that order. The throw is inside `transactions.execute`, so the REVERT run row rolls back, the same as the 409 path does now.
- Risk is low. The frontend maps only `REVERT_NOT_ALLOWED` (`frontend/src/app/shared/labels.ts:29`), and the UI offers revert only for runs that exist (`isOffered`). Users cannot see the change except when they send a bad id.
- The ticket's "test-only" scope is narrower than plan 20.1. Its Notes already record this gap so that someone can decide on it. A one-method production fix plus a unit test is the minimal correct closure.

## What would change my mind
Evidence that a client depends on 409 for an unknown run id, or an ADR that defines revert of an unknown run as a conflict.
