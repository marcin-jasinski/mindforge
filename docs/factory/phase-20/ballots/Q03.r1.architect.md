## Reasoning
- AppProperties.RateLimits is a flat requests/window pair with @Positive/@NotNull. A nested Auth class with the same shape under rate-limits.auth follows that pattern (AppProperties.java:208-222).
- D01 says one interceptor counts both paths keyed by address. One bucket matches this; B needs two counters or per-path keys, which adds a concept for no named threat.
- C shares the model-call budget (30/min), which is too loose for guessing. It also couples bot/model limits to auth limits.
- Window default PT1M reuses the existing fixed-window and Retry-After semantics. A stricter register-only limit can be added later without breaking A.
- Test risk: ApiFlowTest registers many users from localhost, so it must set a high auth.requests via @TestPropertySource; RateLimitTest style already does this.
