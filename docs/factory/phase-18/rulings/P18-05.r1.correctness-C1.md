## Finding
Blocker, confidence 0.8, src/main/java/dev/mindforge/discord/DiscordListener.java:44. Claim: DiscordConfig builds JDA with `JDABuilder.createLight(token, EnumSet.noneOf(GatewayIntent.class))`, so there is no GUILDS intent and no guild is cached. Each interaction then gets a DetachedGuildImpl/DetachedMemberImpl, `DetachedMemberImpl.getRoles()` throws, and `toCall` fails before the gate. Fix: use `EnumSet.of(GatewayIntent.GUILDS)`.

## Rebuttal
JDA 6.7.0 has no `GatewayIntent.GUILDS` constant, so the fix does not compile. `JDABuilder.<init>(String,int)` stores `intents = 1 | raw`, so bit 1 (GUILDS) is always sent. `createLight` calls only `applyLight()`, which changes the member cache, chunking and cache flags. Guilds are cached and the member is attached.

## Ruling
I examined ~/.m2/repository/net/dv8tion/JDA/6.7.0/JDA-6.7.0.jar with javap. `GatewayIntent` has no `GUILDS` field. The first constant is GUILD_MEMBERS. `JDABuilder.<init>(String,int)` at bytecode 238-241 is `iconst_1; iload_2; ior; putfield intents`. `create(String,Collection)` calls this constructor with `getRaw(intents)`. `createLight` = `create(...).applyLight()`. `applyLight` sets MemberCachePolicy.NONE, ChunkingFilter.NONE, disables all CacheFlags and sets largeThreshold 50. It does not change intents. `setEnabledIntents` also forces bit 1. Thus GUILDS is always on, GUILD_CREATE arrives, guilds and their roles are cached, and the interaction member is not built on a detached guild. The premise of the finding is false, and the proposed fix does not compile. Optional: a code comment in DiscordConfig that tells the reader that JDA always enables GUILDS would help, but it is not a required fix.
