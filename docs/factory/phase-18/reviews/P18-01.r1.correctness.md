- id: C1
  severity: minor
  confidence: 0.6
  location: src/main/java/dev/mindforge/infrastructure/persistence/adapter/ExternalIdentityRepositoryAdapter.java:54
  claim: The catch of the broad DataIntegrityViolationException reports every integrity or data failure (NOT NULL, value too long) as an "identity already linked or email taken" conflict, not only unique violations.
  evidence: Hibernate maps PostgreSQL SQLState 22001 (value too long, e.g. an externalId longer than the VARCHAR(64) column) to DataException and NOT NULL failures to ConstraintViolationException; HibernateJpaDialect converts both to DataIntegrityViolationException. The adapter then throws ExternalIdentityConflictException. The P18-03 resolver contract is "on a unique violation re-read findUserId once and return that user", so for a 65-character id the re-read returns empty and the resolver gets a conflict that has no winning row. The ticket says to translate "a unique violation (on the primary key or on idx_users_email)", not every integrity failure.
  fix: Translate only unique violations. Catch DuplicateKeyException if the Spring version maps unique constraints to it, or check that the root cause is an org.hibernate.exception.ConstraintViolationException with kind UNIQUE (or SQLState 23505), and rethrow other DataIntegrityViolationExceptions unchanged.
