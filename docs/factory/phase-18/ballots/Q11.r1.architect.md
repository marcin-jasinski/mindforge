## Reasoning
- RateLimitInterceptor (api/config) is a ~15-line Caffeine window keyed by user UUID. It is mixed with servlet types (HttpServletRequest, SecurityContextHolder) only in preHandle; the counter is trivial.
- ADR 0019 says the limit lives in the API adapter and does not apply to the CLI. The bot is a new adapter, so it owns its own guard; this matches the adapter-owns-its-edge pattern.
- B touches working web code and invents a shared class, and a placement decision (domain/application/api) for little gain. The only gain is a joint allowance, which is a small cost-bound improvement (worst case 2x per user).
- C leaves model spend unbounded per member; the allowlist (Q04) only limits who, not how much.
- A rejected command must call no application service: the guard runs first in the command handler, replying with a fixed "try again in N s" message.
