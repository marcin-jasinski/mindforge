## Reasoning
- QuizSessionStore has no per-user lookup (QuizSessionStore.java); B edits a domain port, adapter and tests for a lookup no other caller needs (minimal-implementation). "Latest" is also ambiguous with web sessions and sessions still preparing, so `/quiz answer` could grade a session the user did not start in Discord.
- C: ownership stays in the service (`owned(...)`, QuizService.java:225-229), but ids are user input; a mistyped or guessed id is just a NotFound/NotOwner. It adds a typing burden and a displayed id. Not unsafe, but worse usability for the same protection.
- A: the map holds only ids, never reference answers; the adapter cannot even name another user's session, and `next/answer` still call `owned(...)`, so ownership is still enforced by the real service. The map must store kbId with the session id, so a later KB change (Q03) cannot desync the pair. Assumption on Q03: the KB is resolved per call; the map stores the KB used at `/quiz start`.
- Async: use `start` (synchronous) inside `deferEdit/deferReply` (3 s ack, 15 min edit window). This avoids polling `isPreparing`, a second code path and a race. Failure mode: a slow model call beyond 15 min; bound it with a timeout and a fixed error reply. Never call a model inside a transaction: `start` already follows this.
- Failure modes to handle in code: no map entry or expired -> fixed "start a quiz first" reply; `QuizFinishedException` -> evict entry; `NotFoundException`/`NotOwnerException` -> same fixed reply (no existence oracle); double `/quiz start` replaces the entry (old session left to TTL). Restart loses the entry: acceptable under the single-instance ceiling.
- Only `NextQuestion` and `Graded` content is rendered; test that no reference answer is in the reply.

## What would change my mind
Evidence that restarts during a quiz are common (then B), or that the ownership test must be reachable from the adapter (then C).

## Implementation notes
- `DiscordQuizSessions` (adapter, `infrastructure.discord`): `Cache<Long, Active(UUID kbId, UUID sessionId)>` built with Caffeine `expireAfterWrite(quizSessionTtl)`, refreshed on each answer; created in the `@Configuration`.
- `/quiz start`: `event.deferReply(true)`; `quizService.start(kbId, userId, scope)`; store entry; `hook.editOriginal(firstQuestion)`.
- `/quiz answer text:`: look up entry, `quizService.answer(kbId, userId, sessionId, text)`; render `Graded` and next question; evict on `finished`.
- Tests: plain Mockito/real QuizService with in-memory store: user B calling answer with A's session id gets NotOwnerException mapped to the fixed reply; no-entry reply; replacement on second start; reply contains no reference answer.
