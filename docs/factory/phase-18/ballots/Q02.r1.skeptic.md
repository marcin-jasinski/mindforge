## Reasoning
- A adds no credential and no new trust boundary. Each linking option creates a new credential (the code) that needs
  hashing, single use, TTL, never-logged, and rate limiting (Q02 Constraints). Rate limiting is Phase 20 (scope.md
  "Out of scope"), so B/C would ship a guessable-by-volume credential without its brute-force control in this phase.
- The data question has no safe default. D01 provisions on first contact, so any `/link` user already has a
  provisioned account with knowledge bases, quiz sessions and study state. Re-point orphans that data (silent loss,
  forbidden by Q02 Constraints); a merge across `kbId`-scoped tables is a large, untested data migration; refuse
  makes linking useless for every user who tried the bot first. Each needs its own design and tests.
- ADR 0027 already records the cost: "A synthetic address can show as a profile email if a bot account reaches the web
  through account linking (Q02)" — linking opens a new path for the `.invalid` address into the SPA, untested now.
- B/C need a frontend change (extra gate) and a new REST endpoint that the reviewers must audit for ownership and
  token-in-body rules (CLAUDE.md "JWT ... never in response body"; the code is shown once, a subtle exception).
- `minimal-implementation.md` "Build What You Need": `link(...)` with no caller must not ship, so A is the only
  option that matches the plan's four commands (implementation-plan.md:1581-1589) without inventing scope.
- A is fully reversible: `external_identities` PK `(platform, external_id)` (Q13) lets a later phase add `link` and a
  code table additively, with no migration of existing rows. Phase 19 reuses the port unchanged.
- E has a caller and no network surface, but trusts the operator to verify ownership out of band; it is new scope with
  weak verification and no plan task. D is the strongest proof of ownership but the widest change.
- Testability: A's behaviour (two separate accounts) is proven by the existing 18.4 tests; nothing new to fake.

## What would change my mind
Evidence that the human requires existing web users to study their wiki from Discord in Phase 18 (a plan line or
vision acceptance criterion), and agreement to pull per-code rate limiting forward; then B with "refuse if the Discord
identity already owns data, else re-point" is the safe variant.
