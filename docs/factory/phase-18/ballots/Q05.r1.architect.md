## Reasoning
- QuizService.start/begin/next/answer already take (kbId, userId, sessionId) and `owned(...)` enforces ownership (QuizService.java:177-225). Any option keeps that check in the service, so the 18.4 cross-user test stays real.
- A changes no domain port. QuizSessionStore has only insert/find/updateCursor/deleteExpired; B adds a user-scoped query plus Flyway-free but adapter and test work for a convenience pointer. The pointer is UI state, not domain state.
- Caffeine is already in the stack (CLAUDE.md); a single live instance is the stated ceiling (architecture.md), so an in-process map is consistent. Loss on restart costs one re-run of `/quiz start`.
- Storing (kbId, sessionId) in the map makes `/quiz answer` independent of Q03: it needs no kb option. Assumption: Q03 gives `/quiz start` a kb; the map remembers it.
- Ownership still applies: the map is keyed by the resolved internal userId, never the raw Discord id alone, so a stale or foreign entry still hits `owned(...)`.
- Async: use `start` after `deferReply`, then edit the reply (15 min window vs 3 s ack). Simplest; `begin`+poll adds polling and failure states (`isPreparing`) for no user gain. Blocking on a virtual thread is allowed.
- C makes the user type a UUID/short id; a short id needs a new lookup, i.e. B anyway.
- Reply only NextQuestion / Graded fields (QuizService.java:50-53), never QuizSession.

## What would change my mind
Evidence that quiz generation routinely exceeds 15 min, or a decision to run more than one instance (then B).

## Implementation notes
- Adapter class (Q09 package) `DiscordQuizSessions`: Caffeine `Cache<UUID, Current>`, `record Current(UUID kbId, UUID sessionId)`, `expireAfterWrite(quizSessionTtl)`; built in a @Configuration bean.
- `/quiz start`: deferReply -> resolve user -> requireOwner -> `quizService.start(kbId,userId,scope)` -> put (replaces old) -> `next(...)` -> editOriginal with NextQuestion.
- `/quiz answer text`: lookup; on miss reply "no active quiz, run /quiz start"; else `answer(...)`; on `finished` or NotOwner, invalidate. Map NotOwner/expired to fixed replies.
- Tests: user A's entry cannot be used for B's session via QuizService (NotOwnerException); reply contains no reference answer.
