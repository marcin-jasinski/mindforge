## Reasoning
- The question says one allowed-guild member can spend model calls without bound; C leaves that open (Phase 20.3 covers only login/register). Weak on correctness.
- RateLimitInterceptor's window logic is about 12 lines (Caffeine compute on a Window record). It is welded to servlet types only at the edges (request, response headers).
- A copies that small logic into the discord adapter keyed by user id; no servlet types, no change to the web path, easy to remove.
- B touches working web code and adds a shared class, which is more concepts. Shared allowance is not required by the question.
- Same properties give one operator knob; no new settings. Rejected command returns the fixed "try again in N s" reply before any application service call.
