## Reasoning
- A adds no domain port change and no migration; Caffeine is already the in-process cache (tech-stack). Single live instance ceiling makes an in-process map safe.
- Loss on restart costs a 2 h quiz session at most; user re-runs /quiz start. Acceptable.
- Ownership stays in QuizService.next/answer(kbId, userId, sessionId): the adapter only supplies the id it stored for this user plus the caller's own userId. Cross-user test is done at service level through the real owned(...) check, with a handler test that seeds user A's id under user B's key (service must throw NotOwnerException).
- Use start (synchronous) inside a deferred reply (3 s ack, 15 min edit window): fewer moving parts than begin + polling isPreparing.
- Only NextQuestion/Graded content is rendered; no reference answer.
- Assumption on Q03: kbId is resolved before the map is used; key the map by (kbId, discordUserId) or discordUserId only if a user has one active KB. Keying by discord user id mapped to account (D01) is fine.
## What would change my mind
Restart-survival becoming a requirement, or a rule that the ownership test must exercise a user-supplied id (then C).
