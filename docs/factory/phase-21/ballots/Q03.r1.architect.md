## Reasoning
- pom.xml already binds jacoco-check to verify; ci.yml runs a single `mvn -B verify`. A matches this pattern.
- factory.md gate is `mvn -B verify`; only lifecycle binding makes the gate equal to CI.
- B lets local/factory pass while CI fails, which defeats the gate.
- C duplicates work (checks run twice) for log readability only; can be added later.
- Windows leg `mvn -B package` will run validate-bound Checkstyle: acceptable (cheap, consistent); SpotBugs on verify is not hit by package.
- Offline: plugins are resolved once, then -o works; fast loop `mvn -o test` runs Checkstyle at validate, so keep it cheap (or accept) and the escape skip flags documented.
## What would change my mind
Unreadable CI logs or Checkstyle plugin not resolvable offline in the fast loop.
## Implementation notes
pom.xml: checkstyle plugin execution phase validate goal check; spotbugs plugin goal check bound to verify (after failsafe, before/with jacoco-check; order by declaration). Consider adding -Dcheckstyle.skip=true to the `fast` command in .claude/factory.md. Update docs/project/deployment.md § Build with the skip flags.
