## Options
| id | option | correct | fit | simple | risk | reversible |
|----|--------|---------|-----|--------|------|------------|
| A  | separate `e2e` job in ci.yml on push and PR, needs: linux, outside `mvn verify` | 5 | 5 | 4 | 4 | 5 |
| B  | same job, only pull_request and develop pushes | 4 | 3 | 4 | 3 | 5 |
| C  | Maven profile -Pe2e in verify, CI enables it | 3 | 2 | 2 | 3 | 3 |

## Reasoning
- ci.yml already triggers on bare `push:` and `pull_request:`. Option A adds a job and keeps the triggers, so no new trigger concept. Option B adds a filter the file does not use.
- tech-stack.md CI/CD says "build + test on every PR (... Playwright E2E)". A and B both satisfy it. B drops feature-branch pushes, so a failure shows up only after a PR opens.
- The factory gate is `mvn -B verify -DskipFrontend=true` with no SPA. An E2E outside Maven leaves it untouched (constraint met). C needs the SPA, so the gate would need a profile discipline.
- The Windows leg has no Linux Docker, so the E2E belongs on Linux, with `needs: linux`. This reuses the verified build and avoids wasted runs.
- Keeping browsers and compose outside Maven also keeps the hexagonal and test standards intact: unit and integration tests stay in failsafe.
- The cost of A (minutes on every push) is small. Add `concurrency` cancel-in-progress to limit it.

## What would change my mind
Runner minutes or flakiness becoming a problem: then move to B. It is a one-line change, so A is not a trap.

## Implementation notes
- `.github/workflows/ci.yml`: add job `e2e`, `needs: linux`, `runs-on: ubuntu-latest`; build image with `docker compose build`, `docker compose up -d --wait`, run Playwright in `e2e/` (or `frontend/e2e`), upload the report artifact `if: always()`, `docker compose down -v`.
- Keep the suite out of failsafe and surefire includes.
- `docs/project/deployment.md`: add "Run the E2E locally" with the exact compose and `npx playwright test` commands. State that the factory gate does not run it.
