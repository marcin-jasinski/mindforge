## Options
| id | option | correct | fit | simple | risk | reversible |
|----|--------|---------|-----|--------|------|------------|
| A  | Bind checkstyle to validate, spotbugs to verify; one CI verify step | 5 | 5 | 5 | 4 | 5 |

| C  | A plus split CI steps | 5 | 3 | 3 | 4 | 5 |

## Reasoning
- .claude/factory.md gate is `mvn -B verify -DskipFrontend=true`; only a lifecycle binding makes the factory gate equal to CI. B lets local and factory pass while CI fails (drift is silent).
- CI today is one `mvn -B verify` step (.github/workflows), and JaCoCo check is already lifecycle-bound in pom.xml. A follows that pattern.
- The fast loop (`mvn -q -o test`) stops before verify, but validate-bound Checkstyle still runs in it. That is acceptable and fast; SpotBugs stays out of the fast loop.
- Risk in A: Windows leg `mvn -B package` runs validate, so Checkstyle runs on CRLF checkouts. Set the line-ending rule to be tolerant (or no NewlineAtEnd/lineSeparator check) so it does not fail on Windows. SpotBugs on verify does not touch the Windows leg.
- Offline: plugins resolve from the local repo after the first download; ensure checkstyle and spotbugs plugin plus their dependencies are fetched once (`dependency:go-offline` style or a first online run).
- C only adds duplicate runs (extra minute for SpotBugs). Splitting for logs is optional later; no need now.
- SpotBugs failures must fail the build (failOnError true) and the exclude file should be reviewed, with each exclusion carrying a reason.

## What would change my mind
Evidence that validate-bound Checkstyle cannot be made line-ending-neutral on the Windows leg, or the gate time rising beyond acceptable limits.

## Implementation notes
pom.xml: maven-checkstyle-plugin execution phase validate, goal check, failOnViolation true; spotbugs-maven-plugin execution phase verify, goal check, declared before jacoco-check so order is checkstyle, compile, tests, spotbugs, jacoco (same phase executions run in POM order; in verify put spotbugs above jacoco-check). Keep -Dcheckstyle.skip / -Dspotbugs.skip. Update docs/project/deployment.md § Build. CI stays one `mvn -B verify` step.
