## Reasoning
- Both A and B are correct with D06/D08: they drive `http://localhost:8080` after `docker compose -f compose.yml -f compose.e2e.yml up --wait`, outside Maven, outside `src/test/java`. No hard objection on either.
- Co-location: D06 already fixes the WireMock mappings at `src/test/e2e/model-stub/` (D06 Implementation notes). With A, specs, mappings and the drift-prone answers live in one tree, so a prompt/journey change is reviewed in one place. B splits the E2E across `frontend/e2e/` and `src/test/e2e/`.
- B couples a test-only tool to the product build. `Dockerfile:5-9` runs `npm ci` on `frontend/package-lock.json` and `COPY frontend/ ./`: every Playwright bump or spec edit invalidates the SPA build layer. A Playwright bump churns the app lockfile that `ng update` also owns.
- B and the factory extra gate: `.claude/factory.md` runs `npm test && npm run build` on `frontend/**`. `angular.json:38-39` has `root: ""`, and the `@angular/build:unit-test` builder discovers `*.spec.ts` by glob (I did not verify the default root of that glob). A Playwright `frontend/e2e/*.spec.ts` that vitest picks up makes the gate red. B must name specs `*.e2e.ts` or limit `include`. A is not near that gate.
- A failure modes and how we find them: (1) `Dockerfile:16` `COPY src ./src` sends `src/test/e2e/node_modules`, `test-results/`, `playwright-report/` into the build context, and `.dockerignore` excludes only `frontend/node_modules`. The context gets large and the `COPY src` layer is busted after each local run. Nothing fails, it is only slow. Fix: three `.dockerignore` lines plus `.gitignore` for reports. (2) A second lockfile is a second audit/update surface (conventions.md:15-16 "document why"). It is one devDependency, so the cost is small. (3) There is no factory gate on `src/test/e2e/**`, so a TS error shows only in the CI `e2e` job (D08). That is accepted: D08 put the suite there by design.
- No plan edit for A: plan 21.2 already says `src/test/e2e/` (implementation-plan.md:1784). The doc that must change is `test-writing.md:31-37`. It must tell the failsafe `src/test/java/.../e2e/` layer apart from the browser suite in `src/test/e2e/`, and say that the browser suite is not Java and is not under failsafe. This prevents the confusion D08 warns about.
- Why I changed from C: my round-1 switch condition ("Q06 resolving to B") is met by D06. D08 forbids a Maven-bound suite.
