## Reasoning
- BundleConformanceValidator (131 lines) has INDEX_ENTRY (line 36) and LOG_DATE (line 37). They validate the bundle file grammar of generated index.md/log.md (plan 9b.2). They do not parse wiki page bodies.
- T26 targets page-body heading/section/link definitions. Index entry line shape and "## date" in log.md are a different grammar. The validator is meant to be an independent oracle, so reusing the production parser weakens it.
- A adds heading-level and "line is a link item" API to a pure domain parser only for the sake of one consumer. That is new concepts, plus risk to BundleConformanceValidatorTest.
- C leaves a silent gap: new export code could add regexes unnoticed.
- B is the smallest change. It follows the existing OutboundHttpGuardTest allowlist pattern. The rule stays strict everywhere else, and the exception is named and reasoned. It is easy to reverse into A later.
