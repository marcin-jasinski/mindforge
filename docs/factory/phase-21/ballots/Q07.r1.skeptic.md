## Reasoning
- Standard already decides the path: `docs/standards/testing/test-writing.md:36` "src/test/java/.../e2e/ — full stack; @Tag("e2e")",
  and `pom.xml:332` failsafe includes `**/e2e/**/*Test.java`. Only the plan text (`implementation-plan.md:1784`) disagrees.
- Determinism is the main failure mode of a browser journey with 8 model-driven steps. C lets the suite reuse
  `support/StubAIGateway` + `Prompts.java` + `ApiFlowTest.givenAnswers()` (CLAUDE.md § Testing: "Use StubAIGateway").
  A/B need a second, non-Java copy of the prompt-fragment routing (fake OpenAI server, Q06 B) or a fake in `src/main` (Q06 A,
  a production-security risk per web-security.md). A second copy drifts silently from `Prompts.java`.
- A adds a Node project inside the Maven source tree: second lockfile, second dependency surface for audits/updates, against
  conventions.md "minimal dependencies". B is cleaner than A but puts a browser-test dependency into the tree the Dockerfile
  `npm ci` installs (`Dockerfile:7`), and the `frontend/**` extra gate (`npm run build`) breaks if a tsconfig picks up `e2e/`.
- D is incorrect: the factory gate `mvn -B verify -DskipFrontend=true` has no `classpath:/static/index.html` (SpaConfig.java:20),
  so a bound browser test is red there by design. C must exclude `e2e` by default (failsafe `excludedGroups`/profile).
- C weak points (how it breaks, how we find out): (1) Playwright Java downloads browsers on first run - CI needs an explicit
  install step + cache, else a network flake looks like a test failure; (2) if Q14 picks A (a fixture
  `src/test/resources/static/index.html`), test-classes precede classes on the classpath and the fixture shadows the real SPA
  in the E2E - the first assertion on rendered Angular content must fail loudly, or Q14 picks B; (3) C does not test the
  Docker image/compose wiring - accept, the Windows/Linux `mvn package` and Dockerfile build already cover that.
- Reversible: a JUnit class plus one test dependency; moving to Node later is a rewrite of one spec, no prod change.

## What would change my mind
Q06 resolving to B (fake OpenAI server via compose) as the panel choice: then the Node binding in `frontend/` (B) runs
naturally against compose and C's main advantage (StubAIGateway reuse) is gone.
