| id | option | correct | fit | simple | risk | reversible |

| A  | separate e2e job, every push and PR, needs linux, outside mvn verify | 5 | 5 | 4 | 4 | 5 |

| C  | mvn verify behind -Pe2e | 3 | 3 | 2 | 3 | 3 |
## Reasoning
- ci.yml triggers on `push:` and `pull_request:`; A matches it. B leaves factory/* branch pushes untested, so an E2E break is found only at PR time.
- tech-stack.md line 189 says E2E runs on every PR. A and B both meet this.
- Factory gate is `mvn -B verify -DskipFrontend=true` (factory.md). Anything bound to verify, even behind a profile, risks the gate; C adds profile drift (a flag someone must remember).
- A separate job fails visibly and isolates browser and Docker flakiness from the coverage-gated linux job. It does not block the fast gate.
- Failure mode of A: flaky E2E turns every push red. Mitigate with upload of the Playwright trace and report as artifacts (if: always()), and pinned browser versions.
- Windows leg has no Linux Docker, so the job must be Linux only.
## What would change my mind
Evidence that CI minutes or flakiness are a real problem; then B.
## Implementation notes
Add job `e2e` in .github/workflows/ci.yml, `needs: linux`, ubuntu-latest, build image via compose, run Playwright from src/test/e2e (npx, not Maven), upload trace artifacts if always(). Document the local run in docs/project/deployment.md.
