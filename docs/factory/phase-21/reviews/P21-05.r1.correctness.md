  location: src/test/java/dev/mindforge/unit/architecture/ArchitectureTest.java:86
  claim: `callMethod(IngestRunRepository.class, "findUnfinished")` matches only call sites whose bytecode owner is exactly `IngestRunRepository`, so a call through the concrete `IngestRunRepositoryAdapter` type (or a sub-interface) is not caught.
  evidence: ArchConditions.callMethod(Class owner, ...) builds `target(owner(type(owner)))`, which is exact-type equality on the call-site owner. `IngestRunRepositoryAdapter` is a public class (constructed in infrastructure/config/PersistenceConfig.java:76). If a class in `dev.mindforge.infrastructure..` that is not a controller held `IngestRunRepositoryAdapter adapter` and called `adapter.findUnfinished()`, the bytecode owner would be `IngestRunRepositoryAdapter`. Rule 3 would pass, but T25 would be broken. This cannot happen on current code (the only callers are RunWorker:106,116, which use the port type), so the rule is not vacuous. It only has a gap for a future violation.
  fix: Use `callMethodWhere(target(name("findUnfinished")).and(target(owner(assignableTo(IngestRunRepository.class)))))` (and the same for `knowledgeBasesWithQueuedRuns`). Or accept the gap, because the adapter is reached only through the port bean.
