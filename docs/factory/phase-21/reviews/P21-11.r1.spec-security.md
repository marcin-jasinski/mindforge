- id: S1
  severity: minor
  confidence: 0.6
  location: .github/workflows/ci.yml:60
  claim: The new `e2e` job runs code from the pushed branch or PR (`npm ci` install scripts, `docker compose build`, Playwright specs) with the default `GITHUB_TOKEN` scope, because neither the workflow nor the job sets `permissions:`.
  evidence: `grep -rn permissions .github/` finds nothing. On `push` and on same-repository `pull_request` runs, the token gets the repository default scope, which can be read/write on older or reconfigured repositories. The job only needs to read the repository and upload an artifact (upload-artifact does not need `GITHUB_TOKEN` write scopes). Fork PRs are safe: `pull_request` (not `pull_request_target`) gives a read-only token and no secrets. The job uses no secrets. The compose log and unmatched dump in the artifact contain only throwaway values from `compose.e2e.yml` (`e2e-not-a-key`, `e2e-throwaway-jwt-secret...`). The missing block is pre-existing for `linux`/`windows`; the new job copies that pattern.
  fix: Add `permissions: contents: read` at workflow level (or on the `e2e` job).
