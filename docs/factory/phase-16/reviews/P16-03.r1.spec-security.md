- id: S1
  severity: major
  confidence: 0.7
  location: src/main/java/dev/mindforge/infrastructure/parsing/ImageExtractor.java:50
  claim: accept(byte[], String) decodes untrusted upload bytes with ImageIO.read before any dimension or pixel bound, so a small decompression-bomb image can exhaust the heap (OutOfMemoryError is an Error, not caught by `IOException | RuntimeException`).
  evidence: Uploads are capped at 50 MB (application.yml:11 `max-file-size: ${UPLOAD_MAX_SIZE:50MB}`), but a PNG of one flat colour with header 40000x40000 compresses to a few KB. ImageIO.read allocates the full raster (40000*40000*4 bytes ≈ 6.4 GB) before the 64 px / 5 MB checks in emit() run. The catch at line 51 catches only IOException|RuntimeException, so OutOfMemoryError propagates out of the parse and degrades the whole JVM shared by all tenants. Every DOCX picture will reach this path once P16-05 wires the helper; the ticket chose "decode to check decodability", so the bound must exist here. D05 notes already allow reading dimensions before decode.
  fix: Open an ImageReader via ImageIO.createImageInputStream/getImageReaders, read getWidth(0)/getHeight(0) from the header first, and skip (WARN, no bytes) images whose width*height exceeds a fixed pixel cap (for example 50 megapixels) before calling reader.read(0); dispose the reader in finally. Add a test with a crafted large-header image.
- id: S2
  severity: minor
  confidence: 0.5
  location: src/main/java/dev/mindforge/infrastructure/parsing/ImageExtractor.java:60
  claim: PNG/JPEG pass-through trusts the declared MIME type, not the decoded format, so bytes of another format declared as image/png or image/jpeg are emitted unchanged with a wrong MIME type, against D05 "re-encode every other decodable raster to PNG".
  evidence: accept(gifBytes, "image/png") -> ImageIO.read succeeds (GIF reader) -> line 60 PNG.equals(mimeType) -> emit(gifBytes, "image/png") returns GIF bytes labelled image/png; the vision provider then receives a mismatched type, the failure D05 "Why" says the filter exists to prevent. DOCX content types and PDF filters come from the file, which the uploader controls.
  fix: Decode with an ImageReader and pass through only when reader.getFormatName() matches the declared MIME (png / jpeg); otherwise re-encode to PNG.
