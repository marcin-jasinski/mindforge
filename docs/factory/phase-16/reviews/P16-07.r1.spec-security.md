Checked:
- AC1: `VERSION = "1"`, `TIER = ModelTier.VISION`; `ImageDescriber.class` is added to `ModelServiceVersionTest`.
- AC2: there is one `gateway.complete(TIER, prompt, image, DeadlineProfile.BACKGROUND)` call, and the prompt renders `title` and `context`.
- AC3: the description goes through `TextRules.singleLine` (NFC, invisible characters removed, whitespace collapsed, trim; it does not truncate) and gets the `MARKER = "Image: "` prefix.
- AC4: `relevant == false` gives `NotRelevant` and ignores the description.
- AC5: a null or blank completion is checked before `ModelJson.read` (which would throw an NPE on null). Only `ModelOutputException` is caught. A null `relevant`, or a null, blank or over-1000-char description, gives `Unusable`. The text is never truncated.
- AC6: there is no broad catch, so gateway and deadline exceptions propagate. The tests assert `isSameAs`.
- AC7: the prompt starts with `# Task: image description`. It wraps the context in `<context>` and declares it, and any text in the image, as data, not instructions. It states the language rule, the relevance rule, the JSON-only answer and the no-marker rule.
- AC8: the bean is wired through `background(aiGateway, backgroundPermits, observationRegistry, ImageDescriber.class)` plus `promptLoader`, as with `relevanceGuard`.
- Scope: nothing calls the service from `IngestPipeline`, and the change adds no `Agent` interface and no placeholder text (P16-08 and option C stay out of scope).
- Security: no API surface. The image bytes go only through the `AIGateway` VISION tier. The title placeholder is handled the same way as in the existing `relevance_guard` prompt.
