## Reasoning
- The port is `AIGateway.complete(ModelTier, String, DeadlineProfile)` (`domain/port/AIGateway.java`). A multimodal chat
  completion is still one single-shot call, so ADR 0013 ("Every call stays single-shot, so `AIGateway` ... unchanged")
  and `ai_agents.md:64` ("chat completion only") are kept in spirit: same verb, same tier/deadline contract, one overload.
- B names the concept: CLAUDE.md "Use `record` for value objects"; a `(byte[], String)` pair that always travels together
  is a value object. It keeps the port to four arguments, parallel to the existing method. A's two loose parameters
  (`byte[]`, `String`) are only mirrored by `DocumentParser.parse(String mimeType, byte[] content)`, and swap-prone.
- C is speculative generality (`minimal-implementation.md`: "No Speculative Abstractions"); nobody sends several images,
  and it rewrites the call path of every existing text caller and every decorator.
- D drops the tier from the call site, which contradicts "Request models by role" and the plan wording.
- Tier enforcement: CLAUDE.md "Every rule a prompt teaches is enforced in code" and the code-owns-the-rules stance argue
  the gateway rejects an image sent to a non-VISION tier rather than silently sending pixels to a text model. Check in
  `AIGatewayAdapter` (the one real implementation) so decorators stay pure pass-through.
- Decorators: `PermitGateway` and `TracingGateway` each gain a trivially-delegating overload with the same permit/span
  logic as today (factor the body into a private helper taking a `Supplier<CompletionResult>`), so span name and cost
  entry stay keyed on the service name.

## What would change my mind
If Q02 puts the image bytes on `ContentBlock` as a typed sub-record that already is `(bytes, mimeType)`, reuse that type
instead of a new `ImageInput` (same shape, B's spirit). Evidence that a second image-per-call use is planned would favour C.

## Implementation notes
- `src/main/java/dev/mindforge/domain/model/ImageInput.java`:
  `public record ImageInput(byte[] data, String mimeType)` — compact constructor: non-null, non-empty data, non-blank
  mimeType starting with `image/`; defensive `data.clone()` in and in accessor; override `equals/hashCode/toString`
  (Arrays.equals/hashCode; toString shows mimeType and length only, never bytes).
- `AIGateway`: add `CompletionResult complete(ModelTier tier, String prompt, ImageInput image, DeadlineProfile deadline);`
  (abstract, not default — every implementor must decide).
- `AIGatewayAdapter`: if `tier != ModelTier.VISION` throw `IllegalArgumentException` (programming error, caller bug).
  Build `new Prompt(UserMessage.builder().text(prompt).media(new Media(MimeTypeUtils.parseMimeType(image.mimeType()),
  new ByteArrayResource(image.data()))).build(), options)`; share the existing `callWithDeadline` + result mapping via a
  private `complete(Prompt, String model, DeadlineProfile)` so Retry, CircuitBreaker and the deadline race are identical.
- `PermitGateway`, `TracingGateway`: new overload delegating through the same permit / observation helper.
- `StubAIGateway`: overload matches answers on prompt fragment like today; `Call` gains a nullable `ImageInput image`
  field (keep a 4-arg convenience constructor or update call sites) so tests can assert the image was sent.
- `AIGatewayAdapterTest`: `shouldRouteVisionTierToItsConfiguredModelStringForImageCall` (capture `Prompt`, assert model
  and that the `UserMessage` carries one `Media` with the MIME type) and `shouldRejectImageOnNonVisionTier`.
