## Options merged
- The architect's "A: `ImageInput image` component" and the skeptic's "A: nullable `ImageInput image` component" are the
  same option, merged under A. The question's raw `byte[] data` variant (architect A2, skeptic A0) is the same idea
  (a new typed component on `ContentBlock`) but with a raw array; D03/ADR 0021 require `ImageInput` for any image
  carried in a document block, so A is read as "typed component of type `ImageInput`". Nobody voted for the raw array.
- B (base64 in `mediaRef`) and the `data:` URI variant of B are merged under B.

- all: C would put bytes on the text paths — `Preprocessor.java:27` keeps non-blank content, so base64 would flow into chunking — confirmed

## Eliminated
- C: verified hard objection (all three ballots): base64 in `content` is non-blank, survives `Preprocessor.java:27`, and is read as text downstream if an IMAGE block is ever undescribed.
- B: verified hard objection (skeptic): it carries an image in a document block without `ImageInput`, against accepted ADR 0021 Consequences; also the generated `ContentBlock.toString` would dump megabytes of base64 into logs and assertion messages.
