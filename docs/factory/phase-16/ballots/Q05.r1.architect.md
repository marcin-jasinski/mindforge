## Reasoning
- Q05 context: each image costs a VISION call plus a background permit (PipelineConfig); an unbounded count is an unbounded run cost.
- ai_agents.md:91 sets the pattern: over a cap the run fails (claim cap, IngestPipeline.java:248-250, via ProcessingSettings.maxClaimsPerExtractCall). A per-document image cap mirrors it exactly.
- Fail, not count-omission: the claim and page-task caps both fail; one rule is easier to keep than two. Omission-counting would need a new run field.
- Filter and dedup are parser/describer concerns: parsers (infrastructure.parsing) drop non-raster and sub-minimum images and re-encode to PNG with JDK ImageIO (no new dependency); dedup by content hash is in the describe step so repeated headers cost one call. Dropped-by-filter images are decoration, not content, so silent skip is acceptable; document this.
- No opt-out switch: Phase 16 checklist expects descriptions in pages; the cap is the control. Add a switch only on demand.
- D01 keeps bytes in content_blocks, so the parser-side byte cap also protects the JSONB row: skip/fail images over a per-image byte cap (e.g. 5 MB after re-encode).
