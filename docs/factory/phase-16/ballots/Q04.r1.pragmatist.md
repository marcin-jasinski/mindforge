| A  | any image failure fails run (retryable for gateway/deadline) | 3 | 4 | 5 | 3 | 4 |

| C  | fixed placeholder text | 2 | 1 | 4 | 2 | 3 |
## Reasoning
- Existing pattern: partial success is legal and drops are recorded as RunFailure (architecture.md Idempotency; RunFailure.ofItem/dropped). ai_agents.md: omission acceptable is counted on the run.
- A lets one decorative or refused image block a document permanently when the failure is non-retryable (empty output), and each retry re-pays all vision calls (D01 dissent).
- B reuses RunFailure; cost is one catch per image. Keep it small: a gateway/circuit-open or deadline error fails the run retryable (whole provider is down, dropping all images would silently degrade); a per-image empty/unusable output is dropped and counted.
- Edge: if every image dropped and no text remains, throw retryable IngestRunFailedException rather than the non-retryable "no text" error.
- Consistent with D01: "loud failure or counted omission, never silent".
## What would change my mind
Evidence that dropped images make wiki pages materially wrong (then A for simplicity and loudness).
## Implementation notes
ImageDescriber returns per-image result; IngestPipeline records RunFailure.ofItem("describe", position, fixed text) for empty output; add "describe" to FAILURE_STEPS in frontend/src/app/shared/labels.ts. Fixed reason strings only, never provider messages.
