## Reasoning
- D03 binds: ImageInput is the only domain image value and ContentBlock reuses it. So A's byte[] is wrapped in ImageInput, which already fixes the array pitfalls (clone, Arrays.equals, toString without bytes) that make raw A0 risky.
- B/C store bytes in a String: ContentBlock's generated toString/equals would dump or compare megabytes; ContentBlock.java record has no override. C also reaches the text paths (Preprocessor drops blank content, so an undescribed image is silently dropped or, with base64, chunked as text).
- Old JSONB rows lack the field; Jackson record deserialization yields null for a missing component, so no migration. Verify with a test of an old-shape JSON.
- Jackson must (de)serialize ImageInput (byte[] as base64); the compact-constructor validation must not reject the null case. Test round trip.
- Only 4 `new ContentBlock(` call sites exist (grep), so churn is small; keep a 6-arg convenience constructor or update them.
- Failure to watch: Preprocessor.clean rebuilds blocks via canonical constructor; must pass image through, and drop/flag an IMAGE with blank content only after describe (D01 loud failure).
## What would change my mind
Evidence that Jackson cannot round-trip ImageInput cleanly with old rows, or that D03 is reopened.
## Implementation notes
Add `ImageInput image` as last-but-one component of ContentBlock (after mediaType; null for non-IMAGE); factory `ContentBlock.image(ImageInput, int position)` with blockType IMAGE, content "", mediaType = image.mimeType(). Leave mediaRef unused. Tests: old-JSON deserialize, round trip, equals by content, toString has no bytes, Preprocessor passes image.
