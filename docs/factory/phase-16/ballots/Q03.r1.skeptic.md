## Reasoning
- Failure mode 1 (silent bypass): `PermitGateway` and `TracingGateway` (`infrastructure/ai/`) are hand-written decorators. If the new method were an interface `default`, a decorator that forgets to override it would skip the permit or the span and cost entry with no compile error, or drop the image. The method must be abstract so the compiler finds all four implementors (adapter, two decorators, `StubAIGateway`). This rules out E. All other test doubles are `StubAIGateway` (QuizServiceTest:54 etc.), so no other code breaks.
- Failure mode 2 (bad input): A passes `byte[]` and `String` as loose positional arguments. A null/empty array or a non-`image/*` MIME type reaches Spring AI `Media`, fails inside `resilient(...)`, is retried and is recorded as a circuit-breaker failure (`AIGatewayAdapter.callWithDeadline`), so a bad PDF image could open the shared breaker for every KB. B validates in the record's compact constructor (non-empty data, `image/` MIME, defensive copy), so bad input fails before the race, once, and not as a provider fault.
- Failure mode 3 (wrong tier): with a tier parameter, a caller can send an image to SMALL/LARGE. The text model then rejects the request (retries, breaker) or ignores the image and invents a description. The adapter must check `tier == VISION` before `callWithDeadline` and throw `IllegalArgumentException`. `StubAIGateway` must do the same check, so unit tests fail the same way production does. D removes this state by construction, but it breaks the "request models by role" shape that every other call uses and the plan text `AIGateway.complete(VISION, ...)`; B plus a check gives the same safety with a uniform signature.
- C adds list handling, empty-list semantics and a change of the hot text path in every implementor for a need nobody has (`minimal-implementation.md`); more change means more risk in the text path that all current services use.
- `record` with a `byte[]` gets identity `equals` and a `toString` that prints `[B@...`; that is acceptable for a call input (and it keeps image bytes out of logs). Do not override `toString` to print the bytes.
- ADR 0013 / `ai_agents.md` line 49/64: the call is still one single-shot chat completion, so no ADR conflict for A–D.

## What would change my mind
Evidence that Q02/Q01 settle on an image type already in `domain.model` (reuse it instead of a new `ImageInput`), or that the plan owner prefers a tier-less method (D) to remove the tier check.

## Implementation notes
- `src/main/java/dev/mindforge/domain/model/ImageInput.java`: `public record ImageInput(byte[] data, String mimeType)`; compact constructor: `Objects.requireNonNull`, reject `data.length == 0`, reject MIME not starting with `image/`, `data = data.clone()`; accessor `data()` returns a clone.
- `AIGateway`: add abstract `CompletionResult complete(ModelTier tier, String prompt, ImageInput image, DeadlineProfile deadline);` (no `default`).
- `AIGatewayAdapter`: `if (tier != ModelTier.VISION) throw new IllegalArgumentException("An image needs the VISION tier")` before building the request; build `UserMessage.builder().text(prompt).media(new Media(MimeTypeUtils.parseMimeType(image.mimeType()), new ByteArrayResource(image.data()))).build()`; share the result mapping with the text method (extract a private `toResult(ChatResponse, String model, long start)`) and reuse `callWithDeadline`, so the deadline race, Retry and CircuitBreaker apply unchanged.
- `PermitGateway` / `TracingGateway`: same body as the text method, delegating to the image overload (permit taken; span and cost named after the service).
- `StubAIGateway`: implement the overload with the same VISION check; extend `Call` with a nullable `ImageInput image` (text calls record `null`) so tests can assert which image was sent and in which order; answers keep matching on prompt fragment.
- `AIGatewayAdapterTest`: one test that the image call routes VISION to `mindforge.ai.model.vision` (mock `ChatModel`, capture the `Prompt`, assert model string and that the `UserMessage` carries one `Media` with the MIME type); one test that a non-VISION tier throws and `ChatModel` is never called.
