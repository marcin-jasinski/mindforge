## Reasoning
- D03 binds: `ImageInput` is the only domain image value; Q02 reuses it, adds no second type. So A means a typed `ImageInput image` component, not a raw array.
- ImageInput already validates (non-empty, image/ MIME), clones defensively, has content-based equals/hashCode and a toString without bytes. This solves the record-array equality and log-leak problems in the question.
- ImageDescriber can pass `block.image()` straight to the D03 gateway overload. No base64 decode in the domain, no string-typed bytes.
- Jackson writes ImageInput as {data: base64, mimeType}; old JSONB rows lack the field, so it deserializes to null. No migration.
- B overloads `mediaRef` (a reference field) with payload and loses type safety; invalid data surfaces late. C is unsafe.
- Cost: constructor churn. Reduce it with a compact constructor allowing null image and a static factory `ContentBlock.image(position, ImageInput, metadata)`; keep the existing 6-arg constructor as a delegating overload if call sites are many.
- Invariant in the compact constructor: image non-null iff blockType == IMAGE. Keep `mediaType` equal to image.mimeType() (set by the factory) or drop duplication by leaving mediaType null; prefer the factory setting both.

## What would change my mind
Call-site count or Jackson record deserialization of ImageInput's cloning accessor proving painful; then B as a stopgap.

## Implementation notes
- `ContentBlock(BlockType blockType, String content, String mediaRef, String mediaType, Map metadata, int position, ImageInput image)`; static `ContentBlock.image(int position, ImageInput image, Map metadata)` with content "".
- Add a 6-arg delegating constructor (image=null) so existing call sites compile.
- Ensure ImageInput JSON round-trip test, plus old-row (no image field) deserialization test.
- Describer replaces IMAGE with TEXT blocks at the same position before Preprocessor.clean (D01).
