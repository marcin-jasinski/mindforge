- id: C1
  severity: minor
  confidence: 0.6
  location: src/main/java/dev/mindforge/application/service/ArticleFetcher.java:40
  claim: A URL wrapped in Markdown emphasis keeps the closing markers, so the fetcher requests a wrong URL and the link is lost as an HTTP_STATUS skip.
  evidence: MarkdownParser builds TEXT blocks from the raw Markdown source (`ContentBlock.text(source(text, node).strip(), ...)`, MarkdownParser.java:50), so emphasis markers stay in the block text. The URL pattern `https?://[^\s<>\[\]"'`]+` accepts `*`, `_` and `~`, TRAILING_PUNCTUATION does not trim them, and `new URI(...)` accepts `*`, `_`, `~` (unreserved/mark chars). Input block `See **https://example.org/a** now` -> extracted `https://example.org/a**` -> fetched as that path -> 404 -> `reason=HTTP_STATUS`, the real article is never queued. Same for `[t](https://example.org/a)**` -> `https://example.org/a)**` (the `)` is not trailing when `**` follows). The D06 trim list is followed to the letter, so this is a gap in the rule, not a deviation from it.
  fix: Also trim trailing `*`, `_` and `~` (repeat the trim loop so `)**` is removed as a whole), and add a test case with a bold URL.
