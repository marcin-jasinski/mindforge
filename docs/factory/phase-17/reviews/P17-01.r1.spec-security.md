  location: src/main/java/dev/mindforge/infrastructure/security/EgressPolicy.java:119
  claim: check() admits a registry-based authority (URI host == null) when the text before the last ':' is a canonical public IPv4, so the port is never validated and a URI with no host is returned as "admitted", against the ticket's decided rule that a registry-based authority gives HOST.
  evidence: java.net.URI falls back to a registry-based authority when the port is not a valid int, so getHost() is null and getPort() is -1. The port check at line 68 then passes (-1), and checkHost uses hostPart(authority) (line 119) which strips everything after the last ':'; "8.8.8.8" is canonical and public, so line 128 returns without the `host == null -> HOST` check at line 130. Reproduced with the compiled class: `check("http://8.8.8.8:8080x/")`, `check("http://8.8.8.8:abc/")` and `check("http://8.8.8.8:99999999999/")` all return the URI (host=null, port=-1) instead of throwing. Ticket Notes: "A registry-based authority (no server host, e.g. `my_host.example.com`) gives HOST." D02/ADR 0022: the policy fails closed and ports are a constant allowlist; here an unvalidated port string is admitted, and P17-05 receives an "admitted" URI it cannot connect to safely (or that another parser may read with a different port).
  fix: In checkHost, refuse with HOST when `host == null` before the IPv4-literal branch (use `uri.getHost()` only and drop `hostPart`); add `http://8.8.8.8:8080x/` and `http://8.8.8.8:99999999999/` to shouldRefuseAUrlWithoutAValidHost.
