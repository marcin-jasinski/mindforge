- id: S1
  severity: minor
  confidence: 0.5
  location: src/main/java/dev/mindforge/infrastructure/web/HtmlArticleConverter.java:99
  claim: Tag-like text inside RCDATA elements (`<textarea>`, a `<title>` in the body) reaches a TEXT block as a literal `<script>…</script>` string, so D05's "no `<`-tag markup survives" holds only by HTML-parsing semantics, and no test covers or documents this case.
  evidence: A probe with jsoup 1.21.2, using the same boilerplate removal, parsed `<body><textarea><script>t()</script></textarea>` into a TextNode `[<script>t()</script>]` under `textarea`. BlockCollector.head appends every TextNode, so the TEXT block content is `<script>t()</script>`. (`noembed`, `noframes` and `xmp` produce DataNodes and are dropped. Script and style are removed.) The source contains no real script element, so this matches the AC6 "escaped markup appears as literal text" rule. But the converter is the only barrier before Extract (D05), and an attacker page can put tag-shaped text into the model input this way.
  fix: Add `textarea` (and optionally `select`) to BOILERPLATE, because form-control content is not article text. Alternatively, add a test that pins this behaviour as intended literal text.
