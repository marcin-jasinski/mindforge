- id: C1
  severity: major
  confidence: 0.85
  location: src/main/java/dev/mindforge/infrastructure/security/EgressPolicy.java:119
  claim: check admits a URL whose authority has a canonical public IPv4 host and an invalid port (for example `8080x`, `-1` or full-width digits), because a registry-based authority (host null, getPort() == -1) passes the port check and then only the host part is checked.
  evidence: java.net.URI falls back to a registry-based authority when the port text is not ASCII digits, so getHost() is null and getPort() is -1. Line 68 accepts port -1. checkHost takes hostPart(authority), which is "93.184.215.14", a canonical public literal, and returns without an exception. Probe against the compiled class shows `http://93.184.215.14:8080x/` -> OK (host=null, auth=93.184.215.14:8080x), `http://8.8.8.8:-1/` -> OK, and `http://93.184.215.14:８０８０/` -> OK, but Integer.parseInt of those full-width digits gives 8080. This breaks AC3 ("refuses any explicit port other than 80/443"). The returned URI also has a null host. A caller that trusts check (P17-05) then either fails with a non-EgressDeniedException error or, if it uses a lenient parser on the authority text, connects to port 8080.
  fix: In checkHost, never admit a registry-based authority. When host == null, keep the numeric parse so that non-public literals give ADDRESS, and then always throw HOST (move the `if (host == null) throw HOST` before the `return` of the numeric branch, or throw HOST at the end of that branch when host == null). Add `http://93.184.215.14:8080x/` and `http://8.8.8.8:-1/` to shouldRefuseAUrlWithoutAValidHost.
