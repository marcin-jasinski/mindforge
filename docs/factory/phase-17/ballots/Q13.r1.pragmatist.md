## Reasoning
- D02 notes and D04 notes already put an injected resolver in the EgressPolicy constructor (production: InetAddress::getAllByName). A adds no new concept.
- With D04 (HttpClient5 CheckedDnsResolver -> egressPolicy.resolve), the test maps articles.test to a public-looking address for the check and to loopback for connect. Needs care: the check must see a public address while the socket reaches 127.0.0.1. Resolver returns a public-looking address would not connect; so the seam must separate check predicate from connect address, or the test resolver returns 127.0.0.1 and the policy takes an injected Predicate<InetAddress> admitting it (D02 note offers either). Simplest: package-private ctor (resolver, Predicate) used by tests; production ctor fixed to strict isPublicUnicast.
- JDK HttpServer needs no dependency.
## What would change my mind
If the fetcher lives in a different package from EgressPolicy so package-private is unreachable: make the ctor public but not wired by any config.
