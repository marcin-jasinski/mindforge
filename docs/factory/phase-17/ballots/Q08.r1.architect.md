## Reasoning
- D01 (ADR 0024): fetch happens after commit in an AFTER_COMMIT listener on the executor, each article queued via IngestionService.ingest. The parent run is not an anchor, so B is impossible.
- Application layer may import only domain, agent, tx and slf4j; a counter would need a new port. Metrics today come via observation in infrastructure (ObservationRunMeter), Phase 14 owns that.
- A: typed exception (Reason enum, like EgressDeniedException) in the application service, caught per URL, logged at warn/info with URL host and fixed reason, never remote body. One bad article never stops the rest.
- Log URL stripped of query/userinfo to avoid secrets.
## What would change my mind
A requirement for user-visible failure status per article; then a per-document note is a separate design change.
## Implementation notes
Catch typed ArticleFetchException (reason enum: POLICY, TIMEOUT, HTTP_STATUS, CONTENT_TYPE, TOO_LARGE, NO_TITLE, LESSON_EXISTS, DUPLICATE) per URL in the fetch application service; log.warn("article skipped: reason={} host={}"). Defer counters to Phase 14.
