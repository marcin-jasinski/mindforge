## Reasoning
- Plan 17.1 (implementation-plan.md:1523) asks for "allowlist-based URL validator; rejects private IP ranges, `file://`, `data:`". A satisfies every clause: the allowlist is schemes + ports (validation.md:15 "Define what's allowed"), `file:`/`data:` fall out of the scheme allowlist, private ranges fall out of "public unicast only".
- Articles come from arbitrary hosts (question context). A host list adds a property, env var, suffix-matching code, docs and tests that no requirement or user has asked for — minimal-implementation.md: "Build What You Need", "No Speculative Abstractions".
- B is reversible to add later: a new optional property with "empty = all" is additive and does not change A's behaviour. So deferring it costs nothing.
- C makes the feature need two settings to work; the plan names one switch (`ProcessingSettings.fetchExternalArticles`, off by default) — "disabled by default" is already met there.
- I fold D into A: phrase the address rule as an allowlist ("is public unicast") rather than a blocklist of ranges, so it fits validation.md literally.
- Default: no new egress properties at all; only the fetch switch (Q10) and maybe timeout. Less to document in deployment.md.

## What would change my mind
An operator/deployment requirement (deployment.md or an ADR) that egress must be narrowable per environment, or a security reviewer showing the address check cannot be made reliable (then B/C narrows blast radius).

## Implementation notes
- `dev.mindforge.infrastructure.security.EgressPolicy` (plain class, bean in a `@Configuration`): `URI check(String url)` throws `EgressDeniedException` (domain/infra exception with fixed reason text, never the raw URL host in run failures).
- Rules: parse with `URI`; scheme in `Set.of("http","https")` (case-insensitive); no userinfo; port -1/80/443 only; host non-empty; resolve `InetAddress.getAllByName(host)` and require every address `isPublicUnicast`: not `isAnyLocalAddress/isLoopbackAddress/isLinkLocalAddress/isSiteLocalAddress/isMulticastAddress`, not 100.64.0.0/10, not fc00::/7, not IPv4-mapped/compat to a non-public v4, not 0.0.0.0/8, not 169.254.0.0/16 (covered by link-local).
- Return or expose the vetted `InetAddress` so the fetcher connects to that address (pin; avoids DNS rebinding), disable automatic redirects and re-run `check` on each `Location` hop (cap e.g. 3).
- Test seam for the mock server on loopback (Q13): package-private constructor taking a `Predicate<InetAddress>`/resolver, not a production property.
- `EgressPolicyTest` cases: file:, data:, ftp:, http://127.0.0.1, http://[::1], 10/172.16/192.168, 169.254.169.254, 100.64.0.1, [fd00::1], [::ffff:127.0.0.1], :8080, public host passes.
