## Reasoning
- D04 already fixes the resolver as a constructor-injected seam on EgressPolicy (production InetAddress::getAllByName) and CheckedDnsResolver connects only to what the policy resolved. A is that seam; no new concept.
- Test maps articles.test to 127.0.0.1 only at the connect step; the policy still checks a public-looking address, so the real client path is tested once (D04 tests list).
- Caveat: if the resolver returns 127.0.0.1 the isPublicUnicast check would reject it. So the seam must separate "resolve" from "vet": test supplies a resolver returning a public address for the check, and a separate connect mapping (or a Predicate) admits loopback. Keep this package-private/test-only, never AppProperties (D02 note allows Predicate or resolver).
- B weakens the guard in the tested object; C adds a dependency for no gain.
## What would change my mind
If the two-step (check address vs connect address) cannot be built cleanly through CheckedDnsResolver, a package-private Predicate<InetAddress> admit hook (D02 note) is the fallback.
