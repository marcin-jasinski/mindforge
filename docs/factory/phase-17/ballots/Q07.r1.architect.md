## Reasoning
- ai_agents.md Lesson Identity: title (slugified) then filename stem, else reject. A feeds the extracted title as the frontmatter-title key and the last URL path segment as filename fallback, so LessonIdentity.resolve is reused unchanged and never yields a placeholder.
- IngestionService.ingest calls parser.parse(mimeType, content) and uploadPolicy.admit; D05 forbids registering text/html. So an article cannot go through ingest() as-is; a new entry method sharing the lock/dedup/lesson-rule/distinctTitle transaction body (extract a private method) is required, which A names.
- PageRenderer.documentLines renders source_filename in citations; the URL there gives provenance with no migration (B adds migration and DTO work, against minimal-implementation.md).
- uploadedBy: parent's uploader is the only valid user (NOT NULL FK); D01 already passes userId in DocumentAccepted.
- Hash over extracted text is stable across fetches, so dedup works; C breaks it.
- Caveat: final URL cut to 1000 chars; the mimeType text/html is a label only, never re-parsed.
## What would change my mind
A requirement to query/filter articles by URL, or a need for URL beyond 1000 chars, would justify B.
## Implementation notes
- IngestionService: add `UUID ingestArticle(UUID kbId, UUID userId, URI finalUrl, String title, String text, List<ContentBlock> blocks)`; extract shared transaction body from ingest() into a private method taking a prepared ParsedDocument-like input; publish no DocumentAccepted for ARTICLE (D01 no recursion).
- Title metadata: Map.of("title", title) to LessonIdentity.resolve(metadata, lastPathSegment(url)); source = UploadSource.ARTICLE; hash = ContentHash.compute(text.getBytes(UTF_8)); sourceFilename = url.toString() truncated to 1000.
- Catch LessonAlreadyExistsException/LessonIdentityException in the fetcher service and log.
