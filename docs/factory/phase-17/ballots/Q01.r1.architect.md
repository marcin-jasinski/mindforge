## Options
| id | option | correct | fit | simple | risk | reversible |
|----|--------|---------|-----|--------|------|------------|
| A  | Synchronous in `IngestionService.ingest` after the upload commit, only for a new document | 4 | 3 | 4 | 3 | 4 |
| B  | New `DomainEvent.DocumentAccepted` in the upload transaction; `AFTER_COMMIT` listener runs the fetch on a virtual thread via an application `ArticleService` | 4 | 4 | 3 | 4 | 4 |
| C  | After the parent's INGEST run completes (`RunWorker` hook or run-completed event) | 3 | 2 | 2 | 3 | 3 |
| D  | Fetch step inside `IngestPipeline` | 2 | 1 | 2 | 2 | 2 |
| E  | (added) `IngestionService.ingest` hands the fetch to its own virtual-thread executor after commit, no event (like `QuizService.prepare`) | 4 | 3 | 4 | 3 | 4 |

## Reasoning
- The upload contract is asynchronous: `DocumentController` answers `202 Accepted`; runs are queued so the request
  never waits on slow work. A (and C's coupling) puts N third-party timeouts on that request. A also must swallow
  fetch errors after commit so the 202 stays true - an awkward contract for a maintainer.
- B is the codebase's own pattern: `hexagonal.md` §"Domain Events": events published in the same transaction,
  listeners `@TransactionalEventListener(AFTER_COMMIT)`; `RunWorkerTriggers` is the template (listener ->
  `executor.execute(...)`). `DomainEvent` is a `sealed interface` built to take more variants.
- B breaks a dependency cycle that A/E create: the fetcher must call `IngestionService.ingest` for each article, so
  the trigger cannot live in a service that `IngestionService` depends on. Listener (infrastructure) ->
  `ArticleService` (application) -> `IngestionService` is acyclic and keeps `IngestionService` unaware of articles.
- Missed event: the same crash window as A/E (in-process dispatch). ADR 0015 accepts lost events for best-effort
  consumers; an off-by-default enrichment is best-effort. Record this in an ADR (scope allows one) because ADR 0015's
  text names only derived consumers and `hexagonal.md:168` says "The run domain event is `IngestRunQueued`" - still
  true, `DocumentAccepted` is a document event, but the doc must say so.
- Retry/sweep re-queue runs via `enqueue`, not via insert, so B never re-fetches on retry (event only on a new
  insert). Ordering: articles queue after the parent's run, so the oldest-first queue ingests them after the parent.
- C contradicts ADR 0015 amendment "the only run domain event is `IngestRunQueued`" (needs amendment), couples
  `RunWorker` to fetching, and the sweep completes `WRITTEN` runs outside any hook. D: hard objection above.
- E is a close second (precedent: `QuizService` own `newVirtualThreadPerTaskExecutor`), but it grows
  `IngestionService` and mixes article policy into upload acceptance.

## What would change my mind
Evidence that the project rejects new domain-event variants without an ADR amendment of 0015 (then E), or that
the fetch must be visible to the uploader in the 202 response (then A).

## Implementation notes
- `domain/model/DomainEvent.java`: `permits IngestRunQueued, DocumentAccepted`;
  `record DocumentAccepted(UUID documentId, UUID knowledgeBaseId, UploadSource source, Instant occurredAt)`.
- `IngestionService.ingest`: publish `DocumentAccepted` inside the transaction only on the insert branch (not for an
  identical document, not in `submitEdit`, not in `retry`). Publishing always is fine; the gate is the listener's.
- `application/service/ArticleService` (or `ArticleIngestion`): `void ingestArticles(UUID kbId, UUID documentId)`;
  returns at once when `!settings.fetchExternalArticles()` or the document's source is `ARTICLE`/`CONVERSATION`
  (no recursion); reads blocks via `DocumentRepository.findById(kbId, documentId)`; fetches through a domain port
  (e.g. `ArticleSource`, kbId-free since it is not tenant data) with no transaction open; for each article calls
  `IngestionService.ingest(new DocumentUpload(..., UploadSource.ARTICLE, ...))`, catching
  `LessonAlreadyExistsException` (log and skip) and per-URL failures (log, continue).
- `infrastructure/event/ArticleFetchTriggers`: `@TransactionalEventListener(AFTER_COMMIT) onDocumentAccepted(e)` ->
  `executor.execute(() -> articles.ingestArticles(e.knowledgeBaseId(), e.documentId()))`; bean wired in a
  `@Configuration` with the same virtual-thread executor `RunWorkerTriggers` uses.
- New ADR (format of 0021): "Articles are fetched after the upload commits, from a document event"; note the
  best-effort loss window and that retry/sweep never re-fetch. Update `hexagonal.md` §Domain Events.
