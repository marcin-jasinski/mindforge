## Reasoning
- Q06 constraints: off by default, bounded work per upload, omissions logged/counted. Only A meets all with no new concepts.
- C fails the bound: each URL becomes a run (Extract + Write xN) and D01 requires a per-document count cap in AppProperties.
- B adds a content-type to parser mapping, and each parser has its own parse surface (PDF) fed with untrusted third-party bytes. No requirement asks for it. It can be added later by widening a set of allowed types.
- A: CODE blocks excluded, since their URLs are rarely articles. Dropping the fragment gives cheap dedupe. Over-cap URLs are logged with a count (ai_agents.md "omission is counted"). This differs from Phase 16 images (reject the upload) on purpose: a missed article must not reject a committed upload (D01: fetch runs after commit).
- Body cap: stop reading at the cap and fail that URL, never truncate (ai_agents.md "never truncate").
- Settings (maxArticlesPerDocument, maxArticleBytes, connect and total timeouts) go in AppProperties next to ProcessingSettings.fetchExternalArticles. Document them in docs/project/deployment.md. Redirect and address checks are Q04 and D02, not here.

## What would change my mind
Evidence that real target articles are mostly PDF or plain text, or that N=10 is too small for the lesson documents in the sample data.

## Implementation notes
- AppProperties: `maxArticlesPerDocument=10`, `maxArticleBytes=2_097_152`, `articleConnectTimeout=5s`, `articleTotalTimeout=15s`. Validate positive values.
- URL extractor in application or infrastructure: scan TEXT and HEADING block text with one regex for markdown `](url)` and bare `https?://`. Strip trailing punctuation and `)`. Normalise by dropping the fragment. Dedupe with a LinkedHashSet. Take the first N; log `skipped=count` at INFO.
- Fetcher: accept Content-Type `text/html` or `application/xhtml+xml` (ignore parameters); otherwise fail the URL with a fixed log. Read through a bounded stream and throw on exceeding the cap. Failure of one URL never stops the others (D01).
- Tests: extractor (CODE skipped, dedupe, fragment, order, cap and skipped count); fetcher against a mock server (oversize, wrong content type, timeout).
