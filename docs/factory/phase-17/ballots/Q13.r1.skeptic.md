## Reasoning
- D04 pins addresses: CheckedDnsResolver connects to exactly what EgressPolicy.resolve returned. A split (check vs connect) would make the test exercise a different path than production, so it cannot prove the pin.
- D04 tests need both "name mapped to 127.0.0.1 is refused" (strict policy) and "test-admitted host succeeds" (relaxed policy). One injected seam serves both, on the same code path as production.
- Safest form: constructor takes resolver plus Predicate<InetAddress>; AppProperties never sets it; production @Configuration uses the strict one. Add a guard test/grep that the relaxed constructor is unused in main.
- Risk: package-private ctor (D02) lives in infrastructure.security but the fetcher test is in infrastructure.article; use a public ctor documented test-only, or a test-tree factory in the security package.
