## Reasoning
- D01 already fixes "an application service extracts the URLs and fetches them with no transaction open" then calls IngestionService.ingest per article; B contradicts it.
- Port matches UploadPolicy/UploadSanitizer and DocumentParser/ParserRegistry patterns.
- Skeptic gain from A: the application class is tested with a stub port, no HTTP, so SSRF/limit logic (EgressPolicy, DnsResolver pinning, redirects, caps; D04) stays wholly inside the one adapter, and the guard test (D03) can pin HTTP code to that single place.
- C gives no extra testability: extraction in the application class is a pure method testable without HTTP. A domain function is a speculative extra concept.
- Port must return a failure outcome (empty Optional or fixed reason) and never throw, so one bad URL cannot abort the others after commit.
## What would change my mind
Evidence that URL extraction is reused outside the fetcher (then C).
