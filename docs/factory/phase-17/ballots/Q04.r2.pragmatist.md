## Options
| id | option | correct | fit | simple | risk | reversible |
|----|--------|---------|-----|--------|------|------------|
| B  | Resolve + check all addresses, JDK HttpClient connects by name (redirect NEVER), manual redirects (max 5) re-checked per hop | 3 | 3 | 4 | 3 | 5 |
| D-HC5 | Apache HttpClient 5 (Boot BOM) with a `DnsResolver` that returns only `EgressPolicy`-vetted addresses; redirects off, followed in code, re-check per hop, max 5; `spring.http.client.factory=jdk` pin | 5 | 4 | 3 | 4 | 4 |
| D-OKHTTP | OkHttp (already shipped transitively) with an `okhttp3.Dns` that returns only vetted addresses; `Proxy.NO_PROXY`; manual redirects | 5 | 3 | 3 | 2 | 4 |

## Reasoning
- B now conflicts with decided notes: D02 "Expose the resolved, vetted addresses ... so the fetcher connects to them"
  and D03 "check the resolved `InetAddress` ... and connect to that address". B connects by name, so it does not do that.
- Skeptic's "untestable" point is a concrete defect in B: the Q13 test seam injects a resolver into `EgressPolicy`, but the
  JDK client resolves by itself. A test that maps a public name to 127.0.0.1 proves only the check, never the connect.
  With a resolver hook (D-*), the injected resolver is the one the client connects through - one path, one test.
- D-OKHTTP: the built jar ships BOTH `BOOT-INF/lib/okhttp-4.12.0.jar` and `okhttp-jvm-5.3.2.jar` (unzip -l, confirmed this
  round). Both carry package `okhttp3`, so which `OkHttpClient`/`Dns` class loads depends on classpath order. A security
  control must not depend on that. Declaring okhttp directly also pins a version that one of two existing users
  (Spring AI vs OTLP sender) does not expect. Low simplicity gain (no new jar) for a real, hard-to-see risk.
- D-HC5: one Boot-managed artifact, already in the local repo (tally: offline gate works), documented in tech-stack.md per
  conventions.md:15-16. The `DnsResolver` is ~15 lines, the same size as B's check. The only side effect (RestClient factory
  auto-detection) is closed by one property line, or by building the fetcher's client by hand and not exposing it as a factory.
- Redirect half is settled across all ballots and unchanged.

## Round 2
Changed B -> D-HC5. Convinced by (1) the decided D02/D03 implementation notes, which require connecting to the vetted
address, and (2) the skeptic's claim that B's guarantee is untestable, which I traced to the Q13 seam: B's tests cannot
reach the client's own lookup. Between the two D forms, I hold against D-OKHTTP on the split okhttp 4/5 jars I verified.

## What would change my mind
Proof that only one okhttp jar's `okhttp3` classes load deterministically and Spring AI/OTLP both work with a pinned version
(then D-OKHTTP), or a hard project rule of no new runtime artifact this phase (then B with the DNS-cache caveat in an ADR).

## Implementation notes
- `pom.xml`: `org.apache.httpcomponents.client5:httpclient5`, no version (Boot BOM). `application.yml`:
  `spring.http.client.factory: jdk`. Add a line to `docs/project/tech-stack.md` "Key Dependencies Summary" (SSRF pinning).
- `dev.mindforge.infrastructure.security.EgressPolicy` (per D02): `URI check(String url)`, `List<InetAddress> resolve(String host)`
  (reject if ANY address fails `isPublicUnicast`); IP-literal hosts checked in `check`.
- `dev.mindforge.infrastructure.article.EgressDnsResolver implements org.apache.hc.client5.http.DnsResolver`:
  `resolve(host)` -> `egressPolicy.resolve(host).toArray(InetAddress[]::new)`; `resolveCanonicalHostname` -> host.
- Fetcher adapter: `CloseableHttpClient` built in an `@Configuration` with
  `PoolingHttpClientConnectionManagerBuilder.create().setDnsResolver(...)`, connect/response timeouts,
  `disableRedirectHandling()`, no system proxy (`useSystemProperties()` not called); loop max 5 hops on 301/302/303/307/308,
  `current.resolve(location)`, `egressPolicy.check(next)` before each hop; body size cap; fixed failure text.
- Tests: name -> 127.0.0.1 via injected resolver is refused at connect; redirect to 127.0.0.1 refused; `2130706433`, `0x7f.1`,
  `[::ffff:127.0.0.1]` refused.
