## Options merged
- New id **S** = JDK `com.sun.net.httpserver.HttpServer` + an `EgressPolicy` constructor seam that takes an injected
  resolver AND an injected address predicate; the test resolver maps a `.test` name to the server's loopback address,
  the test predicate admits that address; production wiring uses `InetAddress::getAllByName` + `isPublicUnicast`.
- Pragmatist and architect voted "A", but both ballots say the literal A (check sees a public address, connect sees
  loopback) does not work and put a `Predicate<InetAddress>` next to the resolver in their implementation notes
  (pragmatist: `EgressPolicy(Function<String,InetAddress[]> resolver, Predicate<InetAddress> admit)`; architect: same
  with `publicCheck`). Skeptic voted "B" but rewrote B as "injected predicate ... in EgressPolicy ctor, test-only" with
  the same `(resolver, Predicate<InetAddress>)` constructor, not a boolean flag. All three implementation notes
  describe the same constructor, the same test, and the same "never from AppProperties" rule. Same in substance.
- The literal A (split check/connect addresses) and the literal B (boolean "allow loopback" flag) are recorded under
  Eliminated so the audit trail shows why they are not separate options.

## Eliminated
- C (WireMock): verified hard objection from all three — new test dependency; question constraint "minimal
  dependencies"; JDK `HttpServer` covers every case in D09:59.
- Literal A (check sees a public address, connect sees loopback): verified hard objection — D04:52-54 / ADR 0025
  pin the connect addresses to the checked ones; a split needs a second code path and would not test the pin.
- Literal B (boolean allow-loopback flag): not a separate option once rewritten; a flag that admits all loopback is
  wider than needed. Folded into S with the predicate admitting only the one server address.

## Rule applied
Rule 2 (unanimous among remaining, after merge into S); C, literal A and literal B out under rule 1.
